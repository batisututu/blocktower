# Blocktower 디자인·에셋 가이드

- 개정: v0.9 / 2026-09-21. B안 세부 외형·편집 가능한 에셋 원본·Windows 19상태 검증과 독립 검토 결과를 반영했다.
- 상태: **B안 Windows 세부 외형 구현 및 검토 완료(정규화 허용 범위).** 구조 타일·HUD·건축 배경·입체 목재 탑을 실제 앱에 적용했다. [외형 보고서](implementation/Visual_Fidelity_Report_2026-09-21.md)를 현재 증거로 사용한다. Android 및 전체 모션/음향 체험은 미검증이다.
- 시각 정본: [사용자 디자인 시안](디자인시안.png). [B/C 비교 이미지](Blocktower_BlockSkin_B_vs_C_v0.2.png)는 후속 스킨 비교 이력으로 보존하며 새 시안의 외형을 덮어쓰지 않는다. 구체적 우선순위와 미결정 조합은 §11을 따른다.

## 1. 디자인 준비 순서

**최소 화면 디자인과 에셋 규격 → 첫 에셋 세트 제작·핵심 코드 병행 → 통합 플레이 검증**을 따른다. 내부 배치/저장 검사에 사용하는 단색 도형을 임시 그래픽이라 부른다. 이를 이유로 디자인 작업을 뒤로 미루지 않는다. 플레이 관찰에는 실제 사용할 B 셀·HUD·폰트·목재 첫 에셋을 적용한다.

첫 세트는 이후 수정 가능한 원본으로 제작한다. 전체 재질·C 상품·대량 장식의 완성까지 기다리지는 않는다. 화면/셀/앵커 규격을 먼저 맞추면 아트 제작과 GameSession 구현을 병행할 수 있다.

## 2. 시각 정체성과 B/C 정책

퍼즐의 프레임·색·선·클리어 빛을 HUD와 탑에 이어 사용한다. 기존 퍼즐의 컬러 구성·광택·블록형태·보드·UI 배치·VFX·음향을 그대로 복제하지 않는다.

| 구분 | B Structural Frame | C Layered Slab |
|---|---|---|
| 역할 | 기본 무료, 대표 화면/마케팅 기준 | 선택 구매형 코스메틱, 판매 시점·가격 미정 |
| 외형 | Matte, 구조 프레임·미세 chamfer, 작은 화면 가독성 | Matte, 수평 band/layer·미세 구조선 |
| 연출 | Architectural Sweep | Layered Light Sweep 등 전용 장식 |

C는 기본 형태·표면·층판 디테일·Light Sweep·클리어 VFX 세트다. 프리뷰와 완성 줄 표시는 공통 기능이다. 점수·조각 크기·판정·배치 범위·배율·층수·해금·보상·난이도·공급을 바꾸지 않는다. 실제 성능 차이는 별도 측정한다.

## 3. 공통 상태·입력·접근성

- 점유/빈칸/배치 가능/배치 불가/완성 대기 상태는 색상 외에도 윤곽·아이콘·텍스트로 구분한다.
- 완성 줄은 정적인 표시를 기본으로 한다. 반복 점멸을 유일한 신호로 쓰지 않는다.
- 가로/세로 교차 줄은 모두 표시하고 버튼은 실제 제거 줄 수 `[N줄 클리어]`를 보여 준다.
- C 표면 장식은 상태 표시보다 강하게 보이지 않게 한다. 단순화된 상태 표시 옵션은 B/C 공통 무료다.
- B/C는 논리 셀 크기, 조각 앵커, 드래그 오프셋, 스냅 범위, 터치 판정, 토글/버튼 위치를 공유한다.
- 클리어 버튼은 엄지 접근성을 검증하되 조각 드롭과 같은 터치로 눌리지 않도록 입력 영역을 분리한다. 드롭 종료 터치를 클리어 입력으로 재사용하지 않는다.
- 구매로 배치 프리뷰의 정보량, 경고 선명도, 탐색 힌트, 추가 시야를 강화하지 않는다.
- 연출의 총 입력 잠금 시간과 다음 배치 가능 시점은 동일하다. C의 장식 꼬리 효과는 정보를 가리거나 입력을 막지 않는다.
- 프레임 시간·메모리 사용은 B/C 각각 측정한다. 코스메틱 규칙이 같다는 이유로 실행 성능까지 같다고 가정하지 않는다.
- 모션 감소·진동/소리 끄기에서도 같은 정보를 제공한다. 설정은 모든 스킨에 공통 적용한다.
- 플레이 중 스킨 변경은 입력이 없는 안정 상태에서만 적용하며 보드/조각/시드/보상을 바꾸지 않는다.

## 5. 상태별 화면과 검수

화면 방향은 제품 결정 전이다. 첫 검증 시안은 세로형 논리 해상도 360×800을 가정하되, 확정 규격으로 취급하지 않는다.
추가로 320×568과 긴 화면 412×915에서 안전 영역/확대 글꼴/트레이 배치를 점검한다. 터치 목표 크기는 디자인 규격에서 고정한다.

| 비교 장면 | 필수 확인 |
|---|---|
| 기본 플레이 | 점수, 자동/수동, 8×8, 3조각, 클리어 버튼, 성장 표시가 겹치지 않음 |
| 대기 1줄 / 교차 2줄 | 표면 무늬와 상태가 구분되고 버튼 N과 일치 |
| 가로 2줄 + 세로 2줄 + 프리뷰 동시 표시 | C 밴드와 4줄 대기 신호를 구분; 교차 셀과 고스트가 정보를 덮지 않음 |
| 배치 프리뷰 가능/불가 | 손가락 가림 보정과 오배치 취소 인지, B/C 정보 동일 |
| 모든 조각 배치 불가 + 대기 줄 있음 | 게임오버 오인 없이 클리어 행동을 발견 |
| 자동 전환 확인 / 취소 | 현재 N줄·점수 일치, 확정 전 보드 입력 잠김 |
| 클리어/해금/구간 완성 동시 발생 | 중요한 보드 정보 유지, 알림 순서/요약, 입력 복귀 시점 동일 |
| 회색조/색각 시뮬레이션/모션 감소 | 컬러·깜박임 없이 상태와 합법 배치를 구분 |

같은 과제를 B/C 순서를 바꿔 체험시키며 상태 판독 오류, 배치 오류, 첫 클리어까지 시간과 주관적 피로를 기록한다.
작은 표본에서 차이를 못 찾았다는 이유만으로 동등성을 입증했다고 쓰지 않는다. 반복되는 C 특유의 오인이 있으면 판매 전에 장식을 수정한다.
첫 정적 팔레트·글꼴·선/앵커는 §10에 기록했다. 실기기에서의 최소 선 두께·확대 글꼴·색각 비교, 애니메이션 시간·사운드/진동 패턴은 전체 Visual Bible의 남은 납품 항목이다.
블록 색 자체로 퍼즐 규칙이 달라지지 않는다. 색각 검증은 특히 유효/무효 프리뷰, 대기 줄, 버튼 활성, 클리어 유도 상태에 집중한다.

탑 화면은 0/1/9/10/11/13/30층, 부분 구간·대표 선택·잠긴 재질의 이중 해금 표시를 준비한다. 저장 실패·복구, 실제 게임오버와 재시작/탑 선택도 필수 상태다. 전체 편집 가능한 레이아웃·컴포넌트·문구를 납품하고 텍스트를 통짜 이미지에 굽지 않는다.

## 6. 기존 비교 시안의 수정 사항

PNG v0.2는 B/C 표면 콘셉트 비교용이다. 실기기 플레이 화면이나 사용성 검증 결과가 아니다.

| 관찰 | 위험 | 후속 시안 요구사항 |
|---|---|---|
| 1,600×1,000 가로 이미지, 두 8×8 보드 하단에 설명이 겹침 | 마지막 행 형태 판독 방해 | 보드와 설명 영역 분리, 8행 전체 노출; 제작 규격 및 내보내기 배율 표기 |
| C 블록마다 밝은 가로 밴드 반복 | 줄 완성/대기 표시 또는 별도 셀 경계로 오인 가능 | 셀 내부 밴드는 저강도로, 완성 상태는 보드 가장자리 마커+연속 외곽선+줄 수 텍스트로 표현 |
| B 프레임의 흰 내부선과 C의 반복선 | 축소 시 노이즈·인접 조각 경계 혼동 가능 | 최소 표시 크기에서 선 수/두께/밝기 비교, 과한 내부 디테일 축소 |
| 점수·클리어 버튼·토글·3개 트레이·성장 표시 없음 | 핵심인 수동 클리어 인지성 판단 불가 | 전체 HUD를 포함한 실제 비율 화면 추가 |
| 정적인 배치와 장식 설명만 존재 | 대기·교차·프리뷰·불가 배치와 연출 후 가독성 미검증 | 같은 보드/조각/상태의 B/C 비교 세트 제작 |

원본 PNG는 결정 근거로 보존한다. 위 항목은 수정 지시이며 새 시안 제작이나 실기기 검증이 완료되었다는 뜻이 아니다.

## 7. 납품·원본·라이선스 규격

| 영역 | 반드시 정할 항목 |
|---|---|
| 공통 | 에셋 ID·버전, 원본/내보내기 경로, 기준 크기/표시 배율, 수정 가능한 원본, 라이선스 |
| 퍼즐 | 셀 크기·간격·앵커, 외곽/내부선 두께, 프리뷰 위치, 드래그 오프셋, 상태 오버레이 순서 |
| UI | 패널 늘림 영역, 최소 터치 영역, 안전 영역, 글꼴 확대·긴 한국어/영문 처리, 텍스트를 이미지에 굽지 않는 원칙 |
| 탑 | 카메라 투영/각도, 층 높이·폭, 상하 결합 앵커, 광원·노출·색 관리, 투명 여백, 레이어 순서·그림자 처리 |
| 가져오기 | 색 공간·알파 가장자리, 필터·mipmap·압축, 아틀라스 여백, 실제 가져온 텍스처 메모리 |
| 피드백 | 상태 변화 시작/종료, 보드 정보 유지, 입력 잠금 길이, 효과음 동시 재생, 진동/모션 감소 설정 |

탑은 같은 .blend 장면/카메라/조명 프리셋에서 재생성 가능해야 한다. 구간마다 따로 만든 이미지나 AI 콘셉트 이미지가 자연스럽게 이어질 것이라고 가정하지 않는다.
AI 이미지를 활용한다면 무드/재질 탐색용으로 먼저 쓰고, 최종 조립 모듈은 고정된 제작 규격에 맞춰 제작한다.
실시간 게임에는 프리렌더 결과를 쓰며, 원본 3D 파일을 런타임 필수 에셋으로 추가하지 않는다.

에셋 등록부에는 제작자·출처 URL·라이선스 증빙·다운로드 날짜·원본·수정 내역·게임 내 사용 위치를 남긴다. 무료라는 이유로 권리를 추정하지 않는다. 사용할 개별 폰트/음원/모델의 라이선스를 동봉한다. 코드 의존성도 출처를 기록한다. 후보 출처 링크와 Godot 가져오기 설정은 기술 리서치 §14를 따른다.

## 8. 탑 제작과 피드백

- 4재질 × 다수 창문 × 난간 × 테라스 × 조명 × 지붕 전체 조합을 개별 이미지로 만들지 않는다.
- 초기에는 재질별 외벽/창 프리셋과 별도 상단 마감으로 제한하고, 레이어 합성 가능성은 이음새 샘플로 확인한다.
- 카메라 투영/각도, 바닥·상단 앵커, 층 높이, 가로 폭, 광원 방향, 여백, 그림자, 렌더 해상도를 공통 규격으로 고정한다.
- 직교 투영을 우선 검증 후보로 둔다. 1층 타일/슬롯 레이어 합성과 10층 프리셋을 같은 샘플로 비교해 이음새·그림자·자산 수를 확인한다. 각도·층당 픽셀 수와 레이어 간 그림자 처리 방식은 아트 규격에서 정한다.
- 지붕/첨탑은 실제 최상단 전용이다. 중간 구간의 마감은 위 구간과 결합 가능한 띠장으로 구분한다.
- 부분 구간은 확보한 층수만 표현한다. 9층을 완성된 10층으로 표시하지 않는다. 세부 재사용 방식은 1~9층 샘플로 정한다.
- 부분 구간을 비계로 표현하는 안은 비교 후보이며 건설 대기시간을 뜻하지 않는다. 기본안은 확보 층수 표시다.
- 대표 구간 단독 화면의 기본 마감은 구간 경계 마감이다. 실제 탑 최상단 전용 첨탑을 모든 출품 구간에 복제하지 않는다.
- 화면 근처 구간만 로드/표시하고 전체 뷰는 축약 실루엣과 총 층수, 구간 점프를 사용한다.
- 프리렌더가 자동으로 저메모리를 보장하지 않는다. 목표 기기·텍스처 크기·메모리·프레임 예산은 Phase 3 전 실측 후 고정한다.
- 새 구간은 기본 목재 프리셋을 사용한다. 해금/재질 변경으로 기존 구간을 자동 덮어쓰지 않는다.

실제 탑은 고정 카메라/조명/색 관리의 Blender 원본에서 프리렌더한 2D 모듈을 합성한다. 같은 앵커·크기로 재생성할 수 있어야 한다. 목재+벽돌 경계 샘플 통과 뒤 전체 재질로 확장한다. 알파 가장자리·아틀라스 여백·축소 무아레와 이음새를 검사한다. 필터/mipmap/압축은 에셋별 실측으로 결정한다.

첫 피드백은 배치, 거절, 클리어, 층수 증가, 구간 완성이다. 반복 대기 줄은 정적 표시를 기본으로 하고 화면 흔들림·hitstop·전체 플래시는 기본 제외한다. 최소 효과음은 선택/버튼·배치·거절·클리어·구간 완성·게임오버이며 line_ready는 추가 후보이다. 제작 범위는 §12, 시간 가안은 개발 계획 §4.4, 오디오 재생 기술은 기술 리서치 §12~13을 따른다.

## 9. 상품화와 후속 제작

C는 선택 구매형 외형 세트이며 퍼즐 능력치와 성장 속도를 바꾸지 않는 방향을 유지한다.
첫 퍼즐/첫 구간 완성을 상점 진입이나 구매 팝업으로 가로막지 않는다.
가격, 플랫폼별 상품 ID, 단품/번들 범위, 체험 제공 방식, 출시 시점은 별도 결정한다.
출시 전 구매 성공·취소·보류·실패·중복 콜백·복원·환불/권한 변경을 구현/검증한다.
권한을 이전에 확인한 소유자가 오프라인에서도 사용할 수 있는 캐시 정책과 온라인 재검증 시점을 명세한다.
미확인 권한을 보유로 간주하지 않으며, 복원 대기/권한 변경 시 퍼즐 진행과 영구 성장은 유지하고 필요 시 B로 복귀한다.
플랫폼 간 구매 이전 지원 여부는 명시적으로 정하고 UI 안내와 일치시킨다. 이 문서는 해당 지원을 약속하지 않는다.
판매 구현 착수 시 선택한 결제 연동 수단과 Godot 4.7.2/타깃 플랫폼의 호환성을 확인한다.


대량 파츠, 음악, 시즌 테마, 상점/홍보 이미지·최종 로고는 첫 세트 이후다. 구매/복원 구현의 기술 기준은 기술 리서치 §18을 따른다.

### 조립·가져오기 규격

- 셀 원본 좌상단 `(0,0)`, `64×64`; 외형 2px 안쪽, 프레임 선 2px, 상태선 3px. 보드는 `step = board_width/8`로 동일 배율 사용한다. 색 바탕→프레임→대기 행/열→프리뷰 순서로 그린다. 원본 px와 축소 화면의 선 두께는 다르므로 실기기 최소선 검사가 필요하다.
- 기본 HUD 좌우 여백 16px, 보드 상단 180px; 높이 700px 미만은 130px. 보드 하단과 트레이 사이 최소 36px를 예약해 25px 안내문과 분리한다. 트레이·클리어·탑 진입 사이 12px, 트레이 높이는 기본 86/compact 58px다.
- 목재 공통 폭 160px. 층 `160×40`: 상단 중앙 `(80,0)`, 하단 중앙 `(80,40)` 연결. 기단 `160×24` 위에 층을 쌓고, 지붕 `160×42` 하단을 최상층 상단에 맞춘다. 중간 10층 경계는 `160×12` 띠장만 겹쳐 그리며 층수에 더하지 않는다. 화면 축소는 모든 모듈에 같은 배율을 적용한다.
- 현재 목재는 정면 투영·벡터 색면이며 Blender 조명/색 관리가 적용된 2.5D 결과가 아니다. 후속 2.5D 제작에서 실제 카메라·그림자·알파 여백을 명세하고 이 앵커를 계승하거나 변경 이유를 기록한다.
- SVG 가져오기는 scale 1.0, lossless, mipmap 미생성, alpha border 보정, premultiplied alpha 끔으로 기록된 `.import` 파일을 사용한다. UI 기본 선형 필터. 아틀라스·GPU 텍스처 메모리·기기별 축소 품질은 아직 측정하지 않았다.
- 현재 시안은 정적 표시이며 저장하지 않는다. 자동 확인 모달은 취소 시 보드를 유지하고 모달 동안 배경 키보드 포커스를 막는다. 실제 터치 포인터·드롭·커밋 경계는 W2~W4 구현 후 별도 검사한다.

## 11. 첨부 시안 재현 기준과 제작 관문

### 기준의 우선순위

1. **외형:** [사용자 첨부와 픽셀이 동일한 시안](디자인시안.png)의 재질·빛·입체감·건축 배경·HUD가 기준이다. 기존 `DESIGN.md`와 `bt_assets_b_0_1` 팔레트는 현재 코드의 관찰 기록이며 이 기준을 대체하지 않는다.
2. **게임 규칙:** 8×8·3조각·수동/자동 클리어·성장은 게임/성장 기획을 따른다. 종합 시안의 예시 점수·칸수·메뉴 문구는 실제 규칙에 맞춰 정규화한다. 시안의 스킨별 `3줄 +420/+600/+780` 표현을 보상 차이로 구현하지 않는다.
3. **첫 조합:** 사용자가 2026-09-21에 **B안**을 선택했다. **B×2 구조 타일·웜 아키텍처**로 W4 첫 화면을 구현한다. 방향 선택은 세부 에셋/최종 외형 승인과 구분한다. 이미지의 C ‘미니멀 스톤’과 기존 정책의 C ‘Layered Slab’은 동일 정의가 아니므로 이름만 보고 합치지 않는다. 선택 후 시각 정의를 갱신하되 무료/유료 정책을 자동 변경하지 않는다.
4. **외부 참고:** Mobbin 화면 구성과 Asset Library 후보는 위 기준에 맞는 부분만 사용한다. 라이브러리 외형에 맞춰 원본 시안을 평면화하거나 다른 팔레트로 바꾸지 않는다.

제작 시작값은 360×800 논리 화면, 3배 작업 캔버스 1080×2400, 셀 원본 128×128 PNG를 **가안**으로 둔다. 모듈·텍스처 해상도는 첫 실제 Godot 출력의 선명도와 메모리 측정으로 확정한다. 원본 이미지의 작은 타일을 확대하거나 통짜 화면을 게임 배경에 붙이는 것으로 완료하지 않는다. 원본에 없는 가려진 영역/다른 상태는 같은 재질·조명 규칙으로 제작하고 추정한 부분을 기록한다.

탑의 카메라 각도·층 높이·광원 숫자를 임의로 최종 확정하지 않는다. 원본 목재 탑과 견줄 첫 렌더를 만든 뒤 채택한 수치·재질·렌더러·노출을 원본 장면에 고정한다. 벽돌·금속·크리스탈은 목재 연결 검수 이후 같은 규격으로 확장한다.

### Godot 연결 작업

- `design_preview.gd`의 `_style()`이 맡는 주요 재질 패널/버튼을 `Theme` + 자체 `StyleBoxTexture` 리소스로 연결한다. 모든 버튼을 단색 StyleBoxFlat으로 마무리하지 않는다.
- 셀의 프레임·로컬 음영·재질은 제작한 텍스처로 표현하고, 유효/무효/대기/프리뷰는 별도 레이어로 유지한다. 색 tint로 모든 재질/하이라이트를 동일하게 덮지 않는다.
- 화면 배경은 독립 레이어로 넣고, 점수·클리어 문자는 실제 Label로 유지한다. 스크린샷 속 글자/가짜 버튼을 실제 UI 대신 사용하지 않는다.
- `_draw_tower()`의 정면 SVG는 최종 외형이 아니다. 제작한 투명 모듈과 연결 앵커로 교체하고 10층 경계와 부분 구간을 확인한다.
- [공식 API와 적용 판단](design/Reference_Research_2026-09-21.md#4-godot에-적용할-구현-방식)을 따른다. 외부 애드온이 필요하다고 가정하지 않고, 후보를 도입할 경우 파일·라이선스·버전·import 증거를 별도 등록한다.

외형 대조는 **구도, 블록 재질/베벨, 배경 건축선, HUD 재질/빛, 글자 위계, 탑 실루엣/입체감**의 6개 축을 각각 통과/수정 필요로 기록한다. 전체 분위기가 비슷하다는 평가 하나로 합산 통과하지 않는다. 단색 배경 대체·평면 셀 대체·정면 탑 대체는 해당 축 실패다.

선택 패널을 8×8·실제 문구·목표 화면 비율로 정규화한 기준 화면을 먼저 만들고, 이것이 원본의 외형을 유지하는지 확인한다. 그 다음 실제 Godot 캡처를 같은 상태로 비교한다. 차이 그림은 오차 위치를 찾는 보조 수단이며 글꼴 렌더 차이까지 단순 점수로 평가하거나 허용되지 않은 레이아웃 변경을 숨기지 않는다.

검수는 한 번에 기본/대기/교차/유효·무효/모달과 1/9/10/11층을 묶어 보고, 발견된 결함을 수정한 뒤 재확인한다. **W0 외형 완료는 G_VARIANT·G_ART·G_ENGINE_FIDELITY 통과 후에만 기록**한다. G_DEVICE와 실제 플레이/저장 통합은 각각 후속 범위를 명시한다. 기존 13개 캡처는 기능 시안 증거이며 이 관문의 통과 증거가 아니다.

W4-C까지 **효과음 없는 내부 기능 검사**와 **실제 에셋을 적용한 체험 평가**를 구분한다. 없는 파일을 조용히 무시해 기본 음향 납품을 완료로 기록하지 않는다. 런타임의 누락/미지원 효과는 게임 규칙을 중단시키지 않고 개발 진단에서 확인할 수 있어야 한다.

파티클·상세 탑 조립·창문 점등·C 전용 장식은 P2다. 정적 재질/광원과 다른 반짝임을 추가하기 전에 원본 시안과 비교한다. 최종 납품은 상태별 실제 Godot 캡처, 정상/감소 모션 비교, 음향 동기화·연타 청취 기록을 포함하고 모바일 햅틱·성능 미검증은 따로 표시한다.

## 13. B안 세부 외형 납품 (2026-09-21)

현재 실제 앱은 `game/assets/visual_bible/`를 사용한다. 첫 W4 납품과 W0 합성 시안은 이력으로 보존한다. [상세 보고서](implementation/Visual_Fidelity_Report_2026-09-21.md), [원본·실행 비교](implementation/fidelity_evidence_2026-09-21/comparison.html), [제작 원본·명령](../art_source/visual_bible/README.md)이 이번 결과의 정본이다.

- 6색 구조 타일·빈칸·패널 5종·아이콘 3개: SVG 15개와 PNG 납품본 15개. 잘린 모서리, 베벨, 구조 이음선과 석재 입자를 포함한다.
- 독립 건축 배경 1개: 생성 프롬프트 보존, 화면 비율별 전체 판을 표시해 양쪽 아치를 유지한다. 글자·게임 보드는 분리한다.
- 목재 9모듈: 편집 가능한 Godot 3D 장면과 투명 PNG. 아치 유리창, 목재 골조, 석재, 난간, 잎사귀, 단계별 폭, 실제 메시 UV 지붕 줄눈을 포함한다. 1/9/10/11층과 13층 중간/최상단을 검사했다.
- 런타임 납품은 SVG 15개+PNG 10개+앵커 JSON 1개다. 출처/크기/SHA-256은 manifest에 기록했다. PNG 25개(런타임+표면 납품본)의 출처 메타데이터 누락은 0개다.

Windows 19상태를 검증했고 독립 검토의 창·배경 프레이밍·지붕·목재/식재 수정 4건을 해결했다. 최종 `ship`은 이 수정 목록과 Windows 캡처 범위다. 8×8 규칙·실제 메뉴·문구·세로 비율 적응을 허용한 대조이며 픽셀 동일성, 사용자 최종 승인, Android 품질, 전체 PF 연출 완료를 의미하지 않는다.

후속 기기 확인: [W5 중간 검증](implementation/W5_Device_Interim_Report_2026-09-21.md)에서 Android 13/1080×2400 퍼즐·탑·설정·확인창의 기본 가독성과 잘림을 확인했다. 화면비/노치/큰 글꼴/음향·햅틱 전체 범위는 남아 있다.

### 12.3. 사용자 실기기 지적 후 UI·효과 납품

2026-09-21 최신 레이아웃은 [보드 중심 방향](../art_source/gamefeel/direction.md)을 따른다. B 재질 원본은 유지하되 시안의 좌우 메뉴는 사용자 지시로 폐기했다. 보드 너비는 화면-24px, 메뉴는 상단, 대기 트레이는 실제 조각 크기에 맞춘다. compact 안전 영역·48px 버튼, 다음 드래그 시 이전 보상 제거를 적용한다. 배치140ms/클리어420ms/입력해제280ms, 최대36파편과 합성 음향5종은 [개선 보고서](implementation/GameFeel_Improvement_Report_2026-09-21.md)에 원본·검증을 정리했다. 구체적인 렌더링은 `board_effects.gd`, 음원 재생은 `feedback_player.gd`가 소유한다. 이전 §11~12.2의 수치는 역사적 납품 기록이며 현재 구성과 충돌할 때 이 절을 우선한다. 실기기 음향/햅틱·손가락 조작감 승인은 미완료다.
