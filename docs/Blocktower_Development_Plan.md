### 4.1. 연출 레퍼런스 검토와 착수 전 기준

입력 자료는 [사용자 연출 검토 프롬프트 v0.1](Blocktower_Puzzle_Presentation_Review_Prompt_v0.1.md)이다. 원문은 보존하고, 작업 순서는 이 문서, 실제 에셋 납품은 [디자인 가이드 §12](Blocktower_Design_Asset_Guide.md#12-w4-연출-에셋-준비), 기술 경계·수용 검사는 [기술 리서치 §13/15](Blocktower_Godot_Tech_Research_2026.md)에서 관리한다. 원문의 권장 시간·입자 수는 실측 결과가 아닌 비교 가안이다. 외형의 우선 기준은 기존 사용자 시안이다.

원문 §1~2/22~24/33~34의 이해·정보 위계·반복 피로 원칙은 아래 경계/시간표에, §3~15/27~28의 사건은 평가표에, §16~21/30~31의 기법·동기화·성능은 기술 리서치 §13/15에 반영했다. §25~26/32의 평가·유지/통합/삭제·세 단계 결론은 이 절과 §4.5가 소유한다. §29의 Visual Bible 우선 원칙은 디자인 가이드 §11~12를 따른다.

### 4.3. 연출과 입력·저장의 연결 결정

1. **행동과 결과를 구분한다.** 터치의 선택/버튼 눌림 반응은 즉시 가능하다. Snap 성공음·실제 제거·점수·성장 효과는 `dispatch().ok` 이후만 시작한다. 준비 효과를 먼저 보여도 보드 제거/보상은 앞당기지 않는다. 모션 종료 콜백으로 CLEAR·성장 지급·공급 생성을 호출하지 않는다.
2. **표현용 과거 상태를 보존한다.** 착수 전 CLEARED에는 줄 수/보상/해금만 있었고 제거 위치가 없었다. W4-A에서 아래 payload를 추가했다. 자동 배치 후 즉시 사라진 셀은 before/after 보드 차이만으로 복원할 수 없다. W4-A에서 `_clear`가 제거 직전의 행·열·중복 제거 셀 인덱스/스타일을 사건에 담도록 계약부터 보강한다. UI가 별도 점수·제거 규칙을 다시 구현하지 않는다. 프리뷰와 예상 점수는 core의 읽기 전용 판정/견적 경로를 사용한다.
3. **표시 중복을 막는다.** 세션/사건 ID와 결과 배열 내 순번으로 한 행동의 PLACED→CLEARED→BATCH_SETTLED→SUPPLIED→GAME_OVER를 처리한다. NEW_BEST 전용 core 사건은 현재 없으므로 확정 전후 best 비교로 표시하며 한 run 첫 갱신 때만 배지/음향을 준다. 이미 처리한 사건·화면 재열기·저장 복원은 축하를 재생하지 않는다. 표시 큐는 저장 보상 장부가 아니다.
4. **짧고 명시적인 입력 경계를 둔다.** idle→dragging→committing→settling, 별도 modal/recovery 상태를 presentation 계약에서 정의한다. committing에는 다른 명령을 받지 않는다. 보드/트레이가 확정 snapshot을 표현하고 제거 잔상이 셀을 가리지 않는 지점에서 settling을 끝낸다. 점수 count-up·+층 토스트·장식 꼬리는 입력을 잠그지 않는다. 아직 옛 셀이 보이는 동안 새 배치를 허용하지 않으며 입력을 뒤늦게 자동 실행하는 큐도 두지 않는다.
5. **좌표·취소를 단일 경로로 처리한다.** 터치 offset을 적용한 조각 원점을 Preview와 Drop 모두 사용하고 드래그 이동에 관성 Tween을 넣지 않는다. 두 번째 터치·마우스 에뮬레이션 중복·트레이 밖 release·모달·포커스 상실·뒤로/백그라운드는 계약에 따라 취소/차단한다. 드롭의 release로 클리어 버튼을 누르지 않는다. 토글 확인 뒤 오래된 revision이면 다시 상태를 제시한다.
6. **중단은 최종 상태로 정착한다.** 씬 이탈·백그라운드·모션 옵션 변경 시 Tween/음향·임시 셀을 종료하고 최신 확정 snapshot에서 다시 그린다. 커밋 불확실/충돌은 W3 재조회가 끝나기 전 입력을 열지 않는다. 정상 복원은 초기 공급이나 과거 축하를 재생하지 않는다. 오류/복구 안내는 축하보다 우선한다.
7. **동시 보상을 요약한다.** 보드 제거→점수/+층→해금·구간 요약 순서다. 한 번에 여러 10층 경계를 넘어도 팝업을 연속 강제하지 않는다. 게임오버는 끝난 이유와 최종 결과를 우선하고 축하는 결과 패널에 합친다. 첫 W4에서는 탑 화면으로 강제 이동·긴 구간 조립·새 보상 ACK 저장을 추가하지 않는다.
8. **설정과 규칙을 분리한다.** 모션 감소/SFX 음량·음소거/진동 OFF는 스킨 공통 표시 설정이며 공급 RNG와 독립이다. 별도 설정 저장 계약을 W4-A에서 정의하고 설정 실패로 게임 기록을 초기화하지 않는다. 이번 판 층수 증가가 필요하면 `NEW_RUN` 기준값과 기존 저장 호환 정책을 먼저 정한다. 누적 total_floors를 이번 판 성과처럼 표시하지 않는다.

### 4.4. 첫 구현의 모션 시간표

아래는 원문과 기존 기술 리서치의 범위를 좁힌 **개발 출발 가안**이다. W4-A에서 동일 이름의 효과 토큰으로 관리하고, 지연/피로 관찰 후 값과 이유를 함께 변경한다. 타이밍은 저장 완료 후 시각 시퀀스 기준이며 파일 쓰기 지연을 포함한 전체 반응 시간도 따로 측정한다.

| 사건 | 최초 시간·표현 가안 | 입력·모션 감소 |
|---|---|---|
| Pick | 80~120ms Lift, scale 1.04를 출발값으로 비교 | 위치 추적은 즉시. 감소에서는 정적 선택 윤곽 |
| Drag/Preview | 유효 alpha 0.4+윤곽, 무효는 ×+윤곽/겹침 셀 표시 | 이동 Tween 없음. 색상만으로 구별하지 않음 |
| Snap / 실패 복귀 | 100~160ms / 80~120ms, Ease Out / In-Out | scale 과장은 생략부터 시작. 취소 시 즉시 원복 가능 |
| 버튼 / AUTO | 100~160ms / 120~180ms, Press/Release 상태 분리 | Disabled는 실행 없음, 키보드 포커스 유지. 감소는 즉시 상태 변경 |
| 대기 줄 | 정적 윤곽·가장자리 마커, line_ready는 선택 사항 | 느린 Sweep은 P2 비교. 점멸·연속 음향 없음 |
| 1줄 / 2~3줄 / 4~16줄 | 총 250~400 / 300~420 / 350~480ms. 4+는 한 등급으로 상한 고정 | 보드 정착·다음 입력 목표는 250ms 이내. 꼬리만 이후 지속. 감소는 짧은 fade 또는 즉시 결과 |
| 점수 | 작은 변화 150~250ms, 큰 변화 250~400ms | 다음 입력 시 이전 count-up 정리 후 새 확정 값으로 정착. 입력 잠금 없음 |

총 길이가 달라도 B/C의 보드 입력 해제 기준은 같다. 원문의 ‘4줄+ Micro Shake/Zoom’은 첫 W4에서 제외한다. 1~3줄 카메라 고정, 전체 화면 플래시·hitstop은 사용하지 않는다. 효과는 사건별 주 신호 1개와 보조 1~2개부터 시작한다. 파티클 8~16개도 총 사건 예산 후보이며 셀/줄마다 곱하지 않는다.

### 4.5. 검토 결론: 세 단계

- **즉시 효과가 큰 작업(P0):** 실제 드래그/배치 프리뷰, 수동 대기 줄·버튼 견적, 저장 성공 후 Snap/제거, AUTO 확인, 종료 원인, 실패/복귀. 기존 로직과 화면을 연결해 행동의 원인·결과를 읽을 수 있게 만든다.
- **적은 비용으로 개선할 작업(P1):** 버튼 easing 통일, 차등 클리어, 점수/+층·공급 반응, 기본 효과음·동시 재생 상한, New Best 1회·해금/구간 요약. 진동은 어댑터 연결 후 W5 실기기로 확인한다.
- **나중에 다듬을 디테일(P2):** GPU/CPU 파티클 선택·모양, 느린 대기 Sweep, 상세 창문/구간 조립, C 전용 꼬리, 4+ 미세 카메라. 도입 여부는 가독성·반복 피로·장치 성능으로 결정한다.

유지할 것은 core 규칙·W3 저장·공통 상태 정보·기존 시안 증거다. 통합 대상은 앞으로 생길 중복 Tween/음향 호출과 같은 사건의 알림이며 단일 사건 처리 경로로 묶는다. 실제 플레이 경로에서는 합성 수치·상태 선택 디버그 UI를 분리한다. 기존 시안 파일/에셋은 기준 대조와 과거 검사에 쓰이므로 무조건 삭제하지 않는다.

### 9월 25일 Phase 3 데스크톱 보완·검증

[보완·검증 기록](implementation/Phase3_Desktop_Validation_2026-09-25.md)에 따라 간이 가져오기에서 놓친 타입 추론 파서 오류를 수정하고, 320×568의 작은 구간 그림을 확대 화면으로 볼 수 있게 했다. 전체 탑의 밝은 배경 대비와 3,000층에서 0%로 보이던 소수 재질 비중도 개선했다. 고정 GUT **138개/3,705개 단언**, 별도 프로세스 저장 **35회/46개 점검**, Windows 네이티브 **13화면/120개 점검**이 통과했다. 전체 탑 화면은 30/300/3,000층에서 24회 갱신의 95백분위가 6.42~6.82ms이고 노드 수는 25개로 유지됐다. 이 값은 해상도가 다른 Windows 호스트 관찰값이다. D08 기기 예산, Android 최신 소스 실측과 §2 사람 관찰은 미완료이므로 Phase 3 전체 수용은 보류한다.

### 9월 25일 Phase 3 Android 실기기 마무리

[실기기 보고서](implementation/Phase3_Android_Device_Validation_2026-09-25.md)에 따라 versionCode 8을 SM-N981N에 설치했다. 전체 탑 그림과 설명의 겹침, 미리 채운 구간 번호가 Android 키보드 입력 앞에 남는 문제를 고쳤다. **138개/3,709개 단언**과 실제 30/300/3,000층 상세·확대·전체 탑 화면, 원자적 외형 복사와 재시작, 300번 구간 점프, 큰 글씨·안전 영역을 확인했다. 전체 탑의 125개 화면 제출 간격 p95는 16.70~16.72ms, 상세 화면 최대 PSS는 326,830KiB였고 3,000층 화면 왕복 10회 PSS 변화는 +564KiB였다. 단일 기기 작업 예산은 통과했지만 최소 지원 기기 선정·장시간 측정 및 첫 플레이 사람 관찰이 남아 있으므로 Phase 3 전체 수용 관문은 보류한다.
