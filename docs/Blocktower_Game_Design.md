# Blocktower 게임 기획

- 개정: v0.5 / 2026-09-20. 게임 기획의 중복을 통합한 현재 기준.
- 소유 범위: 게임 콘셉트, 퍼즐 규칙·점수, Phase, 온라인 제품 정책, 공통 용어.
- 성장 상세는 [성장 기획](Blocktower_Growth_Design.md), 시각·제작 기준은 [디자인 에셋 가이드](Blocktower_Design_Asset_Guide.md), 구현 계약은 [기술 리서치](Blocktower_Godot_Tech_Research_2026.md)를 따른다.
- 주요 기존 절 번호는 참조 연속성을 위해 유지했다. 이동한 상세 규칙을 이 문서에 다시 복제하지 않는다.

# 1. 게임 콘셉트

## 한 줄 정의

> **블록을 배치해 줄을 완성하고, 원하는 순간에 직접 클리어하며, 그 성과로 나만의 탑을 영구적으로 쌓고 꾸미는 모바일 퍼즐 게임**

Blocktower는 일반적인 블록 배치 퍼즐의 점수 경쟁에서 한 단계 확장하여,
퍼즐 성과가 `탑의 높이`와 `건축 스타일`로 누적되는 장기 성장 구조를 제공한다.

핵심 차별점은 다음과 같다.

1. 기본값은 `수동 클리어`
2. 이용자가 게임 중 언제든 자동 클리어 ON/OFF 가능
3. 퍼즐에서 지운 줄 수가 실제 탑 층수로 누적
4. 동시 클리어 성과가 건축 재질/외형 성장과 연결
5. 10층 단위로 작은 건축 완성 경험 제공
6. 다른 이용자와 단순 점수가 아니라 `탑 높이`와 `건축 결과물`로 비교

---

# 2. 핵심 플레이 루프

> 블록 배치  
> → 줄 완성  
> → 지금 지울지 더 모을지 판단  
> → 수동 또는 자동 클리어  
> → 점수 획득  
> → 탑 층수 증가  
> → 재질/외형 성장  
> → 10층 구간 완성  
> → 탑 감상/꾸미기  
> → 다음 퍼즐 도전

퍼즐 한 판이 끝나더라도
이미 획득한 탑 층수, 재질, 외형, 완성 구간은 사라지지 않는다.

---

# 3. 퍼즐 시스템

## 3.1 기본 규칙

- 보드: 8×8
- 블록: 3개씩 제공
- 제공된 3개를 모두 사용하면 다음 3개 제공
- 빈칸에만 배치 가능
- 배치 후 이동 불가
- 블록 회전 불가
- 가로 또는 세로 한 줄의 모든 칸이 채워지면 완성
- 제거 후 나머지 블록은 낙하하거나 이동하지 않음
- 시간 제한 없음
- 퍼즐은 오프라인 플레이를 기본으로 설계

---

# 4. 수동/자동 클리어

## 4.1 기본값

최초 실행 기본값:

> **자동 클리어 OFF = 수동 클리어**

이후에는 이용자가 마지막으로 선택한 클리어 방식을 기억한다.

---

## 4.2 수동 클리어

줄을 완성해도 즉시 사라지지 않는다.

완성된 줄은 보드에 그대로 남고,
이용자가 `[N줄 클리어]` 버튼을 누르면
현재 완성된 모든 줄을 한 번에 제거한다.

완성된 줄은 보드 공간을 계속 차지하지만,
다른 가로/세로 줄을 추가로 완성하는 데 활용될 수 있다.

특정 줄만 골라 제거하는 기능은 넣지 않는다.

완성 줄이 0개면 버튼을 비활성화한다. 배치·클리어·전환 확인창은 동시에 실행하지 않는다.
교차 줄과 보상 처리 순서는 35절을 따른다.

---

## 4.3 자동 클리어

자동 클리어 ON 상태에서는
블록 배치로 완성된 줄을 즉시 제거한다.

추가 버튼 입력은 없다.

---

## 4.4 게임 중 ON/OFF 전환

이용자는 게임 중 언제든 자동 클리어 ON/OFF를 변경할 수 있다.

### 수동 → 자동 / 대기 줄 없음
즉시 전환

안내:
`자동 클리어를 켰어요.`

### 자동 → 수동
즉시 전환

안내:
`수동 클리어로 바꿨어요. 완성된 줄은 직접 지워 주세요.`

### 수동 → 자동 / 완성된 줄 대기 중

확인창 표시:

> 자동 클리어로 바꿀까요?  
> 완성된 N줄을 지금 지우고,
> 이후 완성되는 줄은 자동으로 지웁니다.  
> 이번 클리어: +XXX점

버튼:
- 수동 유지
- 지우고 자동 전환

확정 시:
1. 대기 줄 일괄 제거
2. 정상 점수 지급
3. 자동 클리어 ON

취소 시:
아무 변화 없음

---

# 5. 퍼즐 점수

## 5.1 배치 점수

새롭게 채운 칸:

> **1칸 = 1점**

예:
4칸 블록 배치 = +4점

---

## 5.2 클리어 점수

공식:

> 클리어 점수 = 제거한 줄 수 × 100 × 동시 클리어 배율

| 한 번에 제거한 줄 수 | 배율 | 점수 |
|---|---:|---:|
| 1줄 | ×1.0 | 100 |
| 2줄 | ×1.2 | 240 |
| 3줄 | ×1.4 | 420 |
| 4줄 | ×1.6 | 640 |
| 5줄 이상 | ×1.6 유지 | 줄당 160점 |

자동/수동은 동일한 점수 산식을 사용한다.

수동 버튼을 눌렀다는 이유로 별도 보너스를 주지 않는다.

수동은 즉시 지우거나 보류하는 선택이 가능하므로 자동보다 가능한 전략의 범위가 넓다.
동일 산식은 실제 점수·분당 제거 줄 수·해금 시간의 동등성을 뜻하지 않는다. 모드별 결과 분포를 실측한다.
최고점은 기존 단일 기록을 유지하고 판 중 모드 전환을 허용한다. 모드별 순위를 새로 만들지 않는다.

---

# 6. 게임오버 규칙

게임오버는 단순히 `현재 블록을 놓을 수 없음`이 아니라
`클리어를 통해서도 진행할 수 없음`을 기준으로 판단한다.

### 배치 가능 블록 존재
계속 진행

### 배치 가능한 블록 없음 + 완성된 줄 대기 중
게임오버 아님

클리어 버튼 강조

### 배치 가능한 블록 없음 + 대기 줄 없음
게임 종료

남은 조각 중 **하나라도 한 곳에 합법적으로 배치할 수 있으면 계속 진행**한다.
남은 조각을 전부 놓을 수 있는 미래 순서가 있는지 미리 풀어 게임을 끝내지 않는다.
대기 줄이 있으면 실제 클리어 입력 후 보드를 갱신하고 다시 판정한다.
마지막 조각 사용 시 새 묶음을 지급한 다음 판정한다. 연출 중의 임시 상태로 판정하지 않는다.

---

## 7. 성장과 건축

퍼즐 성과가 게임오버에도 사라지지 않는 탑으로 쌓이고, 이용자가 10층 구간의 외형을 선택한다. 높이 환산·재질/파츠 해금·연속 성과·구간/대표 선택·편집·탑 감상의 단일 명세는 [성장 기획](Blocktower_Growth_Design.md)이다.

크래프팅, 재료 파밍, 건설 대기시간, 주민·임대료·내구도 관리, 탑 붕괴, 복잡한 경영 시스템은 현재 범위에서 제외한다.

# 18. 경쟁 구조

높이와 스타일을 합산하여 하나의 종합 점수로 만들지 않는다.

---

## 18.1 영구 탑 높이

지금까지 쌓은 총 층수

역할:

- 장기 성장 기록
- 개인 성취 상징

초기화하지 않는다.

---

## 18.2 주간 성장 경쟁

이번 주 새로 증가한 층수 비교

주간 기록만 초기화하고
실제 탑은 그대로 유지한다.

명칭은 `순수 퍼즐 실력 랭킹`으로 표현하지 않는다.

예:

- 이번 주 성장

---

## 18.3 스타일 경쟁

후순위 기능

이용자가 선택한 대표 10층 구간을 출품한다.

높이와 분리한다.

테마 예:

- 클래식
- 미래 도시
- 판타지
- 아늑한 탑
- 랜드마크

다른 이용자 방문/감상 수요가 확인된 뒤 도입 여부를 결정한다.

## 19. 기술·디자인 기준

Godot/GDScript와 Native 2D 퍼즐·2.5D 프리렌더 탑의 방향을 유지한다. 버전·호환성·저장·플랫폼 검증은 [기술 리서치](Blocktower_Godot_Tech_Research_2026.md), B/C 정책·첫 화면·최소 에셋·제작/권리 규격은 [디자인 에셋 가이드](Blocktower_Design_Asset_Guide.md)가 소유한다.

최소 화면 디자인과 에셋 규격을 먼저 정하고, 실제 사용할 첫 에셋 세트 제작과 핵심 코드 작업을 병행한다. 단색 도형은 내부 로직 검사에 한정하고 디자인 준비를 구현 뒤로 미루는 근거로 쓰지 않는다.

## 35. 퍼즐 사건과 저장의 사용자 계약

## 35.1 한 번의 클리어

클리어 직전 보드에서 완성 가로줄 R과 세로줄 C를 동시에 구한다.
줄 수는 `N = |R| + |C|`, 제거 셀은 두 집합의 합집합이다. 교차 셀은 한 번만 제거한다.
가로·세로 각 1줄의 교차는 15셀 제거, 2줄 보상(+240점, +2층)이다.
8×8 전체가 찬 상태의 경계값은 16줄, 64셀 제거, +2,560점, +16층이다.
점수 예시는 클리어 점수이며 배치 점수는 별도다. N=0이면 보상을 지급하지 않는다.

## 35.2 상태 갱신 순서

1. 입력 시점에 합법 배치인지 검사하고 조각 소진·보드·배치 점수를 갱신한다.
2. 새 완성 줄을 감지하여 현재 묶음 성공 여부를 기록한다.
3. 자동 모드면 완성 줄 전체를 제거하고 점수·성장을 한 사건으로 반영한다. 수동은 대기 상태를 유지한다.
4. 묶음이 소진되었으면 연속 성과를 정산하고 다음 3개를 지급한다.
5. 최종 보드·현재 조각으로 6절의 진행/클리어 유도/게임오버를 판정한다.
6. 논리 상태를 안전하게 저장한 후 피드백을 재생한다. 연출 종료 콜백에서 보상을 지급하지 않는다.

수동 클리어도 3→5→6 순서로 처리한다(조각 묶음은 소진되지 않음).
수동→자동 확인은 대기 줄 클리어와 모드 변경을 한 사건으로 저장한다.
확인창이 열리면 보드 입력을 잠그고, 확정 직전에 줄 수와 표시 보상을 재검사한다.
드래그 중 토글 입력은 드래그를 취소한 뒤 처리한다. 취소 드래그에는 점수를 주지 않는다.

## 35.3 저장·복구

배치/클리어/묶음 공급/편집 확정의 전체 퍼즐·성장 상태를 저장한다. 확정 보상은 게임오버·새 판·재실행 후 유지하고, 미저장 사건을 완료로 표시하지 않는다. 저장 실패는 재시도/복구를 안내하며 조용히 초기화하지 않는다. 자동 전환 확인 취소는 무변화다.

미완료 연출은 복귀 시 생략하거나 짧게 요약할 수 있다. 연출 재생 여부와 보상 지급을 분리한다. 로컬 영구 성장은 앱 삭제·기기 변경 후 복구 약속이 아니다. 파일 세대·스키마·타입 검증·마이그레이션·중복 사건 처리는 기술 리서치 §6~10을 따른다.

## 35.4 구현 검증 사례

테스트 수용 기준은 기술 리서치 §15의 R/S/D 표 한 곳에서 관리한다. 공급 예제 검증 완료와 전체 게임 통합 완료를 구분한다.

## 35.5 재현용 데이터 계약

동일한 시작 상태·버전·실제 공급·행동 기록으로 보드·점수·성장 결과를 재현한다. 로그는 용량을 제한하며 절단 후에도 시작 스냅샷으로 재생 가능해야 한다. 외부 자동 전송이나 순위 인증을 의미하지 않는다. 필드·정밀도·RNG 소유권은 기술 리서치 §9~10 및 공급 명세를 따른다.

# 36. 개발 범위와 검증 관문

아래 Phase 번호를 모든 문서에서 공통으로 사용한다. 아래는 프로토타입 범위와 통과 조건이며 출시 약속이 아니다.

| 단계 | 최소 구현 | 다음 단계 진입 조건 |
|---|---|---|
| Phase 1 퍼즐 | 기본 B 스킨, 배치/수동·자동/저장; 층수 계기 | 35.4 사례와 35.5 재생 검증 통과, 첫 수동 클리어와 막힘 해소를 설명 없이 수행 가능한지 관찰 |
| Phase 2 성장 | 4재질 기본 외벽, 10층 완성, 1개 파츠의 이중 해금 경로 | 첫 30층까지 모드별 소요시간·자발적 탑 확인·해금 경로 이해를 기록 |
| Phase 3 건축 | 고정 카메라, 외벽/창 프리셋, 부분 구간, 대표 구간, 구간 점프 | 30/300/3,000층에서 이음새·가독성·기기 메모리·프레임 시간 확인 |
| Phase 4 온라인 | 검증된 주간 기록, 다른 탑 보기 | 계정·중복 업로드·오프라인 정책·주차 경계·동기화 충돌 규격 및 검증 구현 |
| Phase 5 확장 | 파츠/스타일 경쟁 등 수요 기반 확장 | 방문/편집 수요 확인 후 범위 선택 |

C 스킨의 미리보기는 시각 검증에 포함한다. 실제 유료 판매는 구매/복원 흐름 검증 이후 별도 출시 범위로 정한다.
대량 파츠 제작, 전체 적용/복사 고도화, 연속 성과 장식은 핵심 성장 검증 후 확장한다.

**차별점 검증용 최소 프로토타입은 Phase 1 + Phase 2의 최소 탑 표현**이다.
퍼즐만 완성한 상태로 성장 재미를 판정하지 않는다. 층/구간 카운터, 목재 첫 에셋을 적용한 탑 화면, 구간 완성 토스트를 먼저 연결한 뒤 재질/파츠 검증으로 확장한다.

## 36.1 조각 공급

현재 개발 전 실험안은 [생성 알고리즘 v0.2](Blocktower_Piece_Generation_Algorithm_Design_v0.1.md)다. 29방향/13계열, 계열 가중·Easy 보정·최대 3회 추가 추첨·현재/수동 클리어 후 한 수 보장을 사용한다. 새 공급 때 한 수를 보장하되 트레이 전체 소진이나 영구 생존은 보장하지 않는다. 이전 무보정 v0.1은 [조각 공급 명세](Blocktower_Piece_Supply_Spec.md)와 예제로 보존한다. GameSession 연결은 [W2 보고서](implementation/W2_GameSession_Report_2026-09-21.md)에서 검증했으며 Windows 파일 저장·재실행은 [W3 보고서](implementation/W3_File_Save_Report_2026-09-21.md)에서 검증했다. 실제 UI 연결의 Windows 검증은 [W4 보고서](implementation/W4_Presentation_Report_2026-09-21.md)에 추가했다. 제품 밸런스·전체 체험·모바일 검증은 미완료다. 변경 근거는 [ADR-0002](adr/0002-versioned-board-aware-piece-generation.md)를 따른다.

## 36.2 첫 30층 검증

첫 10층에서 퍼즐과 영구 성장의 관계를 이해하고, 11~20층에서 자동/수동과 두 해금 경로를 경험하며, 21~30층에서 꾸미기/대표 선택의 기회를 제공한다. 여러 판에 걸쳐 도달할 수 있고 탑 진입·편집은 선택이다. 관찰 대상·측정·중단 기준과 미결정 목록은 [개발 계획](Blocktower_Development_Plan.md)에서 관리한다.

## 37.2 온라인 기록

오프라인 성과는 개인 탑에 보존한다. 단말 저장의 누적값을 검증 없이 공개 랭킹에 올리지 않는다.
Phase 1~3은 계정·공개 랭킹을 필수 의존성으로 삼지 않는다.
Phase 4 전에는 아래 항목의 단일 정책과 예외 처리를 확정한다.

| 항목 | 결정할 내용 / 통과 조건 |
|---|---|
| 주차 | 서버 기준 시간대·주 시작·마감·지연 업로드 귀속; 마감 전후 같은 사건이 두 주에 집계되지 않음 |
| 오프라인 제출 | 서버 발급 시드/행동 검증 방식과 유효기간, 미검증 기록 처리; 개인 성장 유지 |
| 중복·변조 | 사건 ID 재전송, 시계 조작, 파일 편집 대응; 로컬 체크섬은 부정 방지 증거로 취급하지 않음 |
| 여러 기기 | 계정 귀속, 충돌 해결, 탑 편집 병합/선택; 누적값 단순 합산 금지 |
| 순위/보상 | 동률·플레이 시간 편향·부정 기록 정정 및 보상 회수 범위; 초기에는 보상 경쟁 확대 보류 |

서버 수신 시각만으로 주차를 정하면 오래 모아 둔 오프라인 기록을 특정 주에 제출할 수 있다.
따라서 수신 주차 채택 여부는 서버 발급 과제/시드의 유효기간, 지연 제출 한도, 재생 검증과 함께 결정한다.
기기 시간 변경, 같은 로그 재전송, 지난 주 기록을 모아 제출하는 사례를 모두 검증해야 한다.

# 38. 공통 용어

| 용어 | 의미 |
|---|---|
| 줄 | 완성된 가로 또는 세로 8칸; 교차해도 두 줄 |
| 대기 줄 | 수동 모드에서 아직 제거하지 않은 완성 줄; 보드에서 계산 |
| 클리어 사건 | 버튼/자동 배치/전환 확인으로 한 번에 제거한 모든 줄과 보상 |
| 묶음 | 함께 공급된 조각 3개; 남은 조각을 모두 사용해야 다음 묶음 공급 |
| 연속 성과 | 새 줄을 완성한 묶음이 연이어 나온 횟수 |
| 재질 진행도 | 해당 동시 클리어 기준을 만족하며 제거한 누적 줄 수 |
| 총 제거 줄 수 | 탑 총 층수와 같은 개인 성장 누적값; 파츠 대체 해금 기준 |
| 구간 | 10층짜리 건축 완성/편집 단위 |
| 경계 마감 | 다음 구간과 결합 가능한 구간 상단 형태 |
| 최상단 마감 | 실제 탑 맨 위의 첨탑/지붕; 구간 경계 마감과 별도 |
