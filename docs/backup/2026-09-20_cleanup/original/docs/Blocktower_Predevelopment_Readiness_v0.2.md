# Blocktower 개발 착수 준비도·첫 구현 계획 v0.2

- 기준일: 2026-09-20. 사전 테스트 이후 갱신한 현재 작업 기준이다.
- 판정: **핵심 코드와 임시 화면의 구현을 시작할 근거는 확보했다. 사람 플레이·모바일 실행·전체 저장 안정성은 아직 검증하지 않았다.**
- 근거: [사전 테스트 결과](Blocktower_Preflight_Test_Report_2026-09-20.md), [기술 적용 명세](Blocktower_Godot_Tech_Research_2026.md), [상위기획 v0.4](Blocktower_Upper_Game_Design_v0.4.md).
- 이 문서는 다음 구현의 범위·순서·완료 조건을 정한다. 이번 검토에서는 게임 프로젝트 생성, SDK 설치, 에셋 제작을 수행하지 않았다.

## 1. 현재 확보한 것과 남은 위험

| 영역 | 현재 증거 | 다음에 필요한 것 |
|---|---|---|
| 공급·배치·종료 보조 판정 | Godot 4.7.2에서 기초 109조건, 배치 353,400회 독립 대조 통과 | 실제 GameSession의 배치→클리어→성장→재공급 순서 통합 |
| 공급 재현 | 40개 지점을 별도 프로세스에서 복원, ID/state 80비교 통과 | 전체 게임 저장의 타입 검증·실패 복구·버전 호환 |
| 공급 분포 | 두 정책 총 300,000조각 점검 통과 | 반복 조각의 체감, 첫 10/30층, 모드별 플레이 관찰 |
| 테스트 도구 | 목표 엔진 + GUT 9.7.1 기본 테스트 6/6 통과 | 새 게임 코드 테스트를 실제 실행하고 실패 시 종료 코드가 실패인지 확인 |
| 작업 환경 | 검토 시작 시 docs만 존재. 임시 4.7.2 실행 파일 존재를 재확인. 이번에 프로젝트 규칙·설계 진입점·ADR 문서 추가 | 지속적으로 쓸 엔진 경로, Git, game/project.godot, 반복 실행 명령 |
| 내보내기 | 표준 템플릿 폴더는 4.6.1.stable만 재확인 | 4.7.2 템플릿·Android 빌드 경로 조합과 실제 기기 실행 |
| 디자인 | B/C 비교 PNG 1장. 폰트·분리 셀·목재 모듈·음원 파일은 현재 프로젝트에 없음 | 최소 HUD·상태 표시·목재 임시 탑. 원본 PNG는 콘셉트 참고용 |

기존 준비도 v0.1의 환경 표는 최초 조사 기록이다. PATH의 4.6.1과 임시 경로의 4.7.2를 혼동하지 않는다. 전체 엔진·애드온 호환, 게임 난이도, 저장 내구성까지 통과한 것으로 확대하지 않는다.

## 2. 착수 조건을 세 단계로 분리한다

| 관문 | 필요한 준비 / 완료 조건 | 현재 판단 |
|---|---|---|
| G0 — 코드 뼈대·규칙 구현 착수 | 기존 규칙과 버전 있는 공급 실험안으로 시작한다. 첫 작업에서 저장소·엔진 경로·테스트 명령을 고정 | 착수 가능. 완성 아트·휴대폰 빌드는 선행 차단 조건이 아님 |
| G1a — 데스크톱 기능·첫 플레이 점검 | W1~W4 완료, 임시 도형 HUD와 목재 탑, 마우스 입력·전체 저장 확인 | 미완료. 모바일 조작이나 최종 사용자 경험의 증거로 확대하지 않음 |
| G1b — 모바일 사람 관찰 | G1a + W5, 한국어를 포함해 상태가 읽히는 HUD, 기기·관찰 과제 준비 | 미완료. 데스크톱 점검은 이 관문을 기다릴 필요 없음 |
| G2 — 아트 양산·범위 확대 | 첫 루프 관찰 기록, 규칙 오해/저장 결함 해결, 목재+벽돌 결합 및 C 상태 비교 | 미완료. 4재질 전체 아트·상점·온라인은 이 증거 이후 |

W1~W6은 기존 Phase를 대체하는 번호가 아니라 작업 묶음이다. 첫 결과물은 **Phase 1 + Phase 2의 최소 목재 탑**이며, Phase 2 전체 완료를 주장하지 않는다.

## 3. 첫 실험 기준과 미결정 항목

아래는 구현을 진행하기 위한 작업 가안이다. 최종 제품 사양이나 사용자 승인 완료로 기록하지 않는다. 변경 시 기준 버전과 이유를 남긴다.

| 항목 | 첫 작업 기준 | 확정·재검토 시점 |
|---|---|---|
| 기술 | Godot 4.7.2, GDScript, Compatibility, 내장 UI/오디오, GUT 9.7.1 고정 | 엔진/GUT 기본 실행은 검증됨. 렌더러 성능은 W5에서 측정 |
| 공급 | `bt_catalog_19_v0_1` + `bt_family_weighted_v0_1`, ID 균등은 비교군 | [공급 문서](Blocktower_Piece_Supply_Research_v0.1.md)의 좌표·가중치·해시·호출 순서 유지. W6 관찰 후 밸런스 검토 |
| 공급 제한 | 3슬롯 소진 후 공급, 동일 ID 중복 허용, 첫 묶음도 동일 정책, 보드 보정 없음 | 모드/스킨/재실행으로 재추첨하지 않음. 보장 공급은 별도 제안 없이는 추가하지 않음 |
| 첫 화면 | 세로, 논리 360×800을 실험 시작점으로 사용. 320×568와 412×915도 확인 | D02: W4 전체 HUD 전에 채택한 방향을 기록. 실제 터치 크기·safe area는 W5 |
| 첫 검증 플랫폼 | Windows 규칙/입력 확인 후 Android 기기 실험을 우선 제안 | D02/D11: 사용 가능한 기기 모델·OS·화면을 W5 전에 기록. 출시 플랫폼 순서와 별개 |
| 타깃·세션 | 첫 관찰 참가자의 블록 퍼즐 경험을 기록하고 첫 10/30층 흐름을 관찰 | D01/D04: W6 전에 목표 이용자, 1인 관찰 시간 상한과 중단 규칙 명시. 현재 값은 미정 |

기기 모델과 타깃 세션 가설이 미정이어도 W1~W3은 진행할 수 있다. 화면 방향 변경은 W4의 재작업 비용이 있으므로 전체 HUD를 확대하기 전에 결정 기록을 갱신한다.

**바로 다음 작업은 W1이다.** 완료 산출물은 실행 가능한 최소 Godot 프로젝트, 버전 고정 기록, 한 명령으로 다시 실행할 수 있는 테스트다. W1에서 상점·온라인·최종 아트까지 범위를 늘리지 않는다.

엔진과 GUT은 [사전 테스트 출처 기록](pretests/results/engine_provenance_2026-09-20.json) 및 [GUT 실행 기록](pretests/results/gut_compatibility_2026-09-20.json)을 따른다. 기존 글로벌 PATH를 무조건 교체하지 않는다. 게임 코드로 옮기거나 데이터 구조를 바꾸면 기존 예제 통과 기록을 그대로 이전하지 말고 새 대상에서 재실행한다.

원래 예제·검사·provenance는 보존하고 새 경로/새 실행 기록을 추가한다. GUT 라이선스도 도입 시 동봉한다. `play_data.json`은 공급열이며 전체 행동 로그가 아니다. 같은 시드 비교와 별도로 전체 State/Action 재생 검사가 필요하다.

상위 `C:/DEV/CLAUDE.md`의 TypeScript 계약/검사 요구는 [프로젝트 규칙](../CLAUDE.md)에서 GDScript와 `game/scripts/core/contracts/`, Godot/GUT 검사로 매핑했다. [설계 진입점](../GAME-DESIGN.md)과 [ADR-0001](adr/0001-godot-baseline-and-contracts.md)을 추가했으며, 실제 계약 코드는 W2에서 작성한다.

## 5. 첫 통합 구현의 레드팀 사례

다음은 아직 실행하지 않은 수용 기준이다. P 번호는 이 문서 전용이며 기술 리서치의 R/S 번호와 구분한다. 상세 정본은 상위기획 §35와 기술 리서치 §6~11이다.

| ID | 실패를 유발할 사례 | 기대 결과 |
|---|---|---|
| P01 | 1행+1열 교차 / 전체 보드 클리어 | 각각 15셀·2줄·240점·2층 / 64셀·16줄·2,560점·16층. 배치 점수 별도 |
| P02 | 마지막 조각 사용 / 전 조각 불가지만 대기 줄 있음 | 먼저 재공급 후 종료 검사 / 클리어 유도, 즉시 종료 금지 |
| P03 | 기존 대기 줄 유지 / 지운 같은 줄 재완성 | 기존 줄로 다음 묶음 성공 중복 집계 금지 / 재완성은 새 성공. 묶음 소진 때 스트릭 1회 정산 |
| P04 | 수동→자동 확인 취소·확정·중복 입력 | 취소 무변화. 확정은 표시 보상+모드 변경 하나의 커밋. 재처리 보상 없음 |
| P05 | 9→10→11층, 한 사건에서 여러 구간 완성, 게임오버/새 판 | 정확한 부분 층수·구간 수, 신규 목재·기존 편집 유지, 영구 성장 유지. 최상단에만 지붕 |
| P06 | 임시 쓰기/검증/백업/교체 전후 실패와 프로세스 종료 | 유효한 이전 또는 새 전체 세대 하나로 복원. 보드만 이동하거나 층수만 중복되는 혼합 상태 금지 |
| P07 | 저장 성공 응답 직전 종료, 재실행·사건 재시도 | 커밋된 사건은 추가 지급하지 않음. 같은 잔여 조각·공급 state 유지 |
| P08 | 타입 오류, 소수 좌표, 범위 밖 값, 손상·미래 스키마 | 로드 경계에서 거부, 원본 보존·복구 안내. 조용히 새 게임으로 덮어쓰지 않음 |
| P09 | 초기 생성·새 판 생성 도중 실패, 로그 절단·버전 변경 | 최초 3조각도 커밋 후 제공. 새 판은 퍼즐 상태만 초기화하고 성장 유지. 절단 후 시작 스냅샷으로 재생 가능. 지원 버전 변환 fixture 유지 |
| P10 | 드래그 중 토글/팝업/백그라운드, 두 손가락, 화면 밖 드롭 | 드래그 취소·보드 뒤 입력 차단, 단일 입력 소유, 실패/취소 시 보드·큐·점수·RNG 무변화. 복귀 시 영구 입력 잠금 없음 |

W2 착수 때 새 판에서 초기화/유지할 필드 표와 action/result 오류 목록을 정의하고 W3 스키마에 연결한다. `session_id`, 단조 사건 순서, 중복/지난 사건 처리, 커밋 성공 여부가 불명확할 때의 재조회 경로를 명시한다. 마지막 사건 ID만으로 임의의 과거 요청에 원래 결과를 반환할 수 있다고 가정하지 않는다. 과거 결과를 보관하지 않는 경우 재적용하지 않고 현재 상태와 이미 처리됨/오래된 요청 결과를 반환하는 계약을 둔다.

새 저장 형식의 최초 구현에서는 가상의 구버전 마이그레이션을 완료했다고 표시하지 않는다. v1 fixture를 보존하고 이후 실제 스키마 변경 때 변환 검사를 추가한다. 파일 교체 실패 주입과 실제 전원 손실 내구성의 검증 범위도 구별한다.

최소 성장에 해금 카운터를 연결할 때는 해금 전 누적·해금 사건의 줄·조건을 만족하는 하위 재질 집계·모든 파츠의 누적 대체 경로를 기술 리서치의 성장 검사로 확인한다. 해금 미구현 상태에서는 층수 검사만으로 Phase 2 전체 통과를 주장하지 않는다.

Action은 배치, 수동 클리어, 자동 전환, 새 판, 편집 확정의 입력과 오류를 먼저 닫는다. 신규 판의 시드는 GameSession에서 한 번 정하고 후보 상태에 보존하며, 저장 재시도마다 새로 뽑지 않는다. 진행 중 새 판의 확인 UX와 설정 초기화 범위도 W2 필드 표에 포함한다. 구간 생성/보상은 클리어 사건에서 완료되므로 `ACK_SEGMENT`는 필수 게임 action이 아니다. 첫 구현의 복귀는 미완료 축하 연출을 생략한다. 나중에 미확인 안내를 재개할 경우에만 별도 표시 확인 상태를 설계하고, 확인 동작으로 보상을 지급하지 않는다.

## 7. 사람 관찰과 이후 조사

W6 전 테스트 계획에는 참가자 조건, 모드 순서 교차, 같은 공급 버전/시드, 관찰 시간 상한, 실패·중단 정의, 기록 보관/전송 여부를 적는다. 첫 안내 이후 수동 클리어 이해, 막힘 해소, 10/30층 도달, 반복 조각 불만, 탑을 자발적으로 보거나 편집하는 행동을 기록한다. 30층은 여러 판에 걸쳐 도달할 수 있다.

6~10명은 초기 관찰 가안이다. 작은 표본이나 공급 분포 통과로 재미·리텐션을 확정하지 않는다. 반복되는 규칙 오해는 HUD/안내 수정으로, 성장 확인 동기 부족은 최소 탑 표현/보상 재검토로 연결한다. 임의 성공률이나 도달 시간 목표를 지금 확정하지 않는다.

D01~D14의 미결정 목록은 [기존 결정 기록](Blocktower_Redteam_Review_2026-09-20.md)에 보존한다. 현재 D03은 실험 명세·단위 검증이 확보된 상태로 진전했고, D02/D06/D13은 W4 준비, D01/D04/D12는 W6 관찰 준비에 연결한다. 클라우드·주간 랭킹·계정·결제·출시 기기 하한은 해당 단계 전에 결정하며 W1을 막지 않는다.
