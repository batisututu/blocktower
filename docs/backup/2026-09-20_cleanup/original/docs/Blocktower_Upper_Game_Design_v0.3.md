# 1. 게임 콘셉트

## 한 줄 정의

> **블록을 배치해 줄을 완성하고, 원하는 순간에 직접 클리어하며, 그 성과로 나만의 탑을 영구적으로 쌓고 꾸미는 모바일 퍼즐 게임**

Blocktower는 일반적인 블록 배치 퍼즐의 점수 경쟁에서 한 단계 확장하여,
퍼즐 성과가 `탑의 높이`와 `건축 스타일`로 누적되는 장기 성장 구조를 제공한다.

핵심 차별점은 다음과 같다.

1. 기본값은 `수동 클리어`
2. 이용자가 게임 중 언제든 자동 클리어 ON/OFF 가능
3. 퍼즐에서 지운 줄 수가 실제 탑 층수로 누적
4. 동시 클리어 성과가 건축 재질/외형 성장과 연결
5. 10층 단위로 작은 건축 완성 경험 제공
6. 다른 이용자와 단순 점수가 아니라 `탑 높이`와 `건축 결과물`로 비교

---

# 2. 핵심 플레이 루프

> 블록 배치  
> → 줄 완성  
> → 지금 지울지 더 모을지 판단  
> → 수동 또는 자동 클리어  
> → 점수 획득  
> → 탑 층수 증가  
> → 재질/외형 성장  
> → 10층 구간 완성  
> → 탑 감상/꾸미기  
> → 다음 퍼즐 도전

퍼즐 한 판이 끝나더라도
이미 획득한 탑 층수, 재질, 외형, 완성 구간은 사라지지 않는다.

---

# 3. 퍼즐 시스템

## 3.1 기본 규칙

- 보드: 8×8
- 블록: 3개씩 제공
- 제공된 3개를 모두 사용하면 다음 3개 제공
- 빈칸에만 배치 가능
- 배치 후 이동 불가
- 블록 회전 불가
- 가로 또는 세로 한 줄의 모든 칸이 채워지면 완성
- 제거 후 나머지 블록은 낙하하거나 이동하지 않음
- 시간 제한 없음
- 퍼즐은 오프라인 플레이를 기본으로 설계

---

# 4. 수동/자동 클리어

## 4.1 기본값

최초 실행 기본값:

> **자동 클리어 OFF = 수동 클리어**

이후에는 이용자가 마지막으로 선택한 클리어 방식을 기억한다.

---

## 4.2 수동 클리어

줄을 완성해도 즉시 사라지지 않는다.

완성된 줄은 보드에 그대로 남고,
이용자가 `[N줄 클리어]` 버튼을 누르면
현재 완성된 모든 줄을 한 번에 제거한다.

완성된 줄은 보드 공간을 계속 차지하지만,
다른 가로/세로 줄을 추가로 완성하는 데 활용될 수 있다.

특정 줄만 골라 제거하는 기능은 넣지 않는다.

---

## 4.3 자동 클리어

자동 클리어 ON 상태에서는
블록 배치로 완성된 줄을 즉시 제거한다.

추가 버튼 입력은 없다.

---

## 4.4 게임 중 ON/OFF 전환

이용자는 게임 중 언제든 자동 클리어 ON/OFF를 변경할 수 있다.

### 수동 → 자동 / 대기 줄 없음
즉시 전환

안내:
`자동 클리어를 켰어요.`

### 자동 → 수동
즉시 전환

안내:
`수동 클리어로 바꿨어요. 완성된 줄은 직접 지워 주세요.`

### 수동 → 자동 / 완성된 줄 대기 중

확인창 표시:

> 자동 클리어로 바꿀까요?  
> 완성된 N줄을 지금 지우고,
> 이후 완성되는 줄은 자동으로 지웁니다.  
> 이번 클리어: +XXX점

버튼:
- 수동 유지
- 지우고 자동 전환

확정 시:
1. 대기 줄 일괄 제거
2. 정상 점수 지급
3. 자동 클리어 ON

취소 시:
아무 변화 없음

---

# 5. 퍼즐 점수

## 5.1 배치 점수

새롭게 채운 칸:

> **1칸 = 1점**

예:
4칸 블록 배치 = +4점

---

## 5.2 클리어 점수

공식:

> 클리어 점수 = 제거한 줄 수 × 100 × 동시 클리어 배율

| 한 번에 제거한 줄 수 | 배율 | 점수 |
|---|---:|---:|
| 1줄 | ×1.0 | 100 |
| 2줄 | ×1.2 | 240 |
| 3줄 | ×1.4 | 420 |
| 4줄 | ×1.6 | 640 |
| 5줄 이상 | ×1.6 유지 | 줄당 160점 |

자동/수동은 동일한 점수 산식을 사용한다.

수동 버튼을 눌렀다는 이유로 별도 보너스를 주지 않는다.

---

# 6. 게임오버 규칙

게임오버는 단순히 `현재 블록을 놓을 수 없음`이 아니라
`클리어를 통해서도 진행할 수 없음`을 기준으로 판단한다.

### 배치 가능 블록 존재
계속 진행

### 배치 가능한 블록 없음 + 완성된 줄 대기 중
게임오버 아님

클리어 버튼 강조

### 대기 줄 제거 후에도 남은 블록을 모두 배치할 수 없음
게임 종료

# 7. 성장 시스템

## 7.1 성장 목표

퍼즐의 결과를 단순 점수로 끝내지 않고
이용자 소유의 영구적인 탑으로 변환한다.

핵심 성장축:

1. 탑 높이
2. 건축 재질
3. 외형 파츠
4. 10층 구간 완성
5. 대표 구간
6. 다른 이용자와의 비교

---

# 8. 탑 높이

## 기본 환산

> **퍼즐에서 실제 제거한 1줄 = 탑 1층**

| 클리어 | 탑 성장 |
|---|---:|
| 1줄 | +1층 |
| 2줄 | +2층 |
| 3줄 | +3층 |
| 4줄 | +4층 |
| 5줄 | +5층 |

동시에 많이 지웠다는 이유로 탑 높이 배율을 추가하지 않는다.

이유:

퍼즐 점수에서 이미 동시 클리어 보너스를 제공하므로
탑 높이는 가장 직관적인 누적 성장값으로 유지한다.

---

# 9. 재질 해금

재질은 소모 재료가 아니다.

한 번 해금하면 계속 사용할 수 있는
`건축 스타일`이다.

재질에 능력치 차이는 없다.

## 기본 계열

- 목재
- 벽돌
- 금속·유리
- 크리스털

아트 표현은 최종 Visual Bible에서 구체화한다.

---

# 10. 재질 해금 방식

재질은 두 가지 경로를 제공한다.

> **동시 클리어 = 빠른 해금 경로**
>
> **누적 플레이 = 느리지만 확실한 대체 경로**

예시:

| 재질 | 빠른 해금 | 누적 대체 해금 |
|---|---|---|
| 목재 | 기본 제공 | 기본 제공 |
| 벽돌 | 2줄 이상 동시 클리어 1회 | 누적 30줄 |
| 금속·유리 | 3줄 이상 동시 클리어 1회 | 누적 100줄 |
| 크리스털 | 4줄 이상 동시 클리어 1회 | 누적 250줄 |

수치는 초기 밸런스 가안이다.

목적:
- 자동/수동 선택 자유 유지
- 특정 외형을 얻기 위해 수동 조작을 강요하지 않음
- 숙련 이용자는 도전으로 더 빠르게 해금 가능

---

# 11. 재질 발전

재질 발전은 `동시 클리어 발생 횟수`가 아니라
`조건을 충족하며 실제로 제거한 줄 수`를 기준으로 계산한다.

## 예시

### 벽돌 진행도
2줄 이상 동시 클리어에서 제거한 줄 수

- 2줄 클리어 → +2
- 4줄 클리어 → +4

### 금속·유리 진행도
3줄 이상 동시 클리어에서 제거한 줄 수

- 3줄 → +3
- 4줄 → +4

### 크리스털 진행도
4줄 이상 동시 클리어에서 제거한 줄 수

- 4줄 → +4
- 5줄 → +5

상위 성과는 하위 재질 진행에도 반영한다.

예:

4줄 동시 클리어

- 벽돌 +4
- 금속·유리 +4
- 크리스털 +4

큰 클리어가 작은 클리어보다 성장에서 불리해지는 문제를 방지한다.

예:

## 크리스털

- 결정형 외벽
- 발광 창

# 13. 연속 성과

연속 성과는 핵심 성장 조건으로 사용하지 않는다.

## 정의

제공된 블록 3개 묶음 안에서
새로운 줄을 1개 이상 완성하면 연속 성공 1회

다음 묶음에서도 완성하면 연속 유지

줄을 완성하지 못하면 종료

## 역할

연속 성과는 선택형 보조 목표다.

보상 예:

- 외벽 패턴
- 조명
- 깃발
- 프로필 배지
- 대표 구간 장식
- 기록 표시

독점 핵심 재질을 연속 성과에 묶지 않는다.

유사 장식은 누적 플레이를 통해서도 얻을 수 있게 설계한다.

---

# 14. 10층 구간

## 핵심 원칙

> **탑 10층 = 하나의 건축 완성 단위**

예:

- 1~10층 = 구간 1
- 11~20층 = 구간 2
- 21~30층 = 구간 3

무한히 숫자만 증가하는 탑이 아니라
이용자가 작은 완성을 반복하도록 한다.

---

# 15. 구간 완성 경험

10층 완성 시:

1. 구간 완성 안내
2. 완성 전/후 비교
3. 새 구간의 외형 확인
4. 해금한 재질/파츠 적용 가능
5. 탑 전체에 새 구간이 결합되는 연출
6. 대표 구간 지정 가능

퍼즐 진행 중에는 건축 편집을 강요하지 않는다.

표시는 간단하게:

- `+3층`
- `다음 구간까지 2층`
- `벽돌 진행 +4`

정도로 제한한다.

# 18. 경쟁 구조

높이와 스타일을 합산하여 하나의 종합 점수로 만들지 않는다.

---

## 18.1 영구 탑 높이

지금까지 쌓은 총 층수

역할:

- 장기 성장 기록
- 개인 성취 상징

초기화하지 않는다.

---

## 18.2 주간 성장 경쟁

이번 주 새로 증가한 층수 비교

주간 기록만 초기화하고
실제 탑은 그대로 유지한다.

명칭은 `순수 퍼즐 실력 랭킹`으로 표현하지 않는다.

예:

- 주간 증축
- 이번 주 성장
- 주간 건축 기록

---

## 18.3 스타일 경쟁

후순위 기능

이용자가 선택한 대표 10층 구간을 출품한다.

높이와 분리한다.

테마 예:

- 클래식
- 미래 도시
- 판타지
- 아늑한 탑
- 랜드마크

다른 이용자 방문/감상 수요가 확인된 뒤 도입 여부를 결정한다.

# 19. 기술 스택 — 승인 확정

## 최종 기본 기술 방향

> **Godot 4.7.2 + GDScript + 2D 퍼즐 + 2.5D 프리렌더 탑**

### 게임 엔진

- Godot 4.7.2 Stable
- MIT 라이선스 기반
- 상업 출시 가능
- 엔진 로열티 없음

### 스크립트

- GDScript

선정 이유:

- Godot와 가장 밀접하게 통합
- 프로젝트 구조가 상대적으로 단순
- AI 코딩 도구가 텍스트 기반으로 다루기 쉬움
- 모바일 2D 퍼즐에 충분한 성능

---

# 20. 그래픽 구조 — 승인 확정

## 퍼즐

> **Native 2D**

구성:

- 2D Sprite
- Tween Animation
- 2D Particle
- UI Animation
- 터치 Drag & Drop

실시간 3D를 사용하지 않는다.

---

## 탑

> **2.5D Pre-rendered Tower**

Blender 등 3D 제작 도구로 건축물을 만든 뒤,
고정된 카메라 각도에서 렌더하여
Godot에서는 2D 이미지로 사용한다.

기본 흐름:

> 3D 건축 모듈 제작  
> → 고정 카메라 렌더  
> → 투명 PNG/WebP  
> → Godot Sprite  
> → 10층 구간 조합

---

# 21. 2.5D 프리렌더 선정 이유

실시간 3D 대신 프리렌더 방식을 선택한 이유:

1. 저사양 모바일에서도 안정적인 성능 확보
2. GPU 부하 감소
3. 배터리/발열 부담 감소
4. 1인 개발 난이도 감소
5. 높은 탑 표현이 쉬움
6. 조명과 재질을 미리 렌더하여 일정한 품질 확보
7. 10층 구간 구조와 매우 잘 맞음

3,000층 규모의 탑도
3,000개의 실제 3D 객체를 렌더하는 것이 아니라
`10층 프리렌더 구간`을 조합해 표현한다.

# 26. Blocktower Visual Identity 목표

퍼즐과 탑을 별개의 게임처럼 보이게 하지 않는다.

퍼즐에서 사용한 디자인 언어를
건축 화면에도 연결한다.

예:

- 퍼즐 블록의 색상 → 탑 조명/장식
- 블록 모서리 형태 → UI 버튼 형태
- 클리어 빛 효과 → 건축 완성 연출
- 동시 클리어 등급 → 재질 이펙트
- 같은 아이콘 선 굵기 → 퍼즐/탑 UI 공통 사용

이를 통해:

> `퍼즐 → 성장 → 건축`

이 하나의 게임 경험으로 보이게 한다.

# 34. 최종 제품 방향

Blocktower는 단순히 Block Blast형 퍼즐에
건물 이미지를 붙이는 게임을 목표로 하지 않는다.

핵심은 다음이다.

> **퍼즐에서 내가 직접 클리어 타이밍을 선택하고,  
> 그 플레이 결과가 사라지지 않는 탑으로 쌓이며,  
> 일정 높이마다 나만의 건축물을 완성하고,  
> 그 결과를 다른 이용자와 높이와 스타일로 비교하는 경험.**

기술적으로는:

> **Godot 4.7.2 + GDScript + Native 2D Puzzle + 2.5D Pre-rendered Tower**

그래픽적으로는:

> **Blocktower 전용 Visual Bible을 기반으로 기존 퍼즐 게임과 명확하게 구분되는 독자적인 시각 정체성을 구축한다.**
