# 1. 게임 콘셉트

## 한 줄 정의

> **블록을 배치해 줄을 완성하고, 원하는 순간에 직접 클리어하며, 그 성과로 나만의 탑을 영구적으로 쌓고 꾸미는 모바일 퍼즐 게임**

Blocktower는 일반적인 블록 배치 퍼즐의 점수 경쟁에서 한 단계 확장하여,
퍼즐 성과가 `탑의 높이`와 `건축 스타일`로 누적되는 장기 성장 구조를 제공한다.

핵심 차별점은 다음과 같다.

1. 기본값은 `수동 클리어`
2. 이용자가 게임 중 언제든 자동 클리어 ON/OFF 가능
3. 퍼즐에서 지운 줄 수가 실제 탑 층수로 누적
4. 동시 클리어 성과가 건축 재질/외형 성장과 연결
5. 10층 단위로 작은 건축 완성 경험 제공
6. 다른 이용자와 단순 점수가 아니라 `탑 높이`와 `건축 결과물`로 비교

---

# 2. 핵심 플레이 루프

> 블록 배치  
> → 줄 완성  
> → 지금 지울지 더 모을지 판단  
> → 수동 또는 자동 클리어  
> → 점수 획득  
> → 탑 층수 증가  
> → 재질/외형 성장  
> → 10층 구간 완성  
> → 탑 감상/꾸미기  
> → 다음 퍼즐 도전

퍼즐 한 판이 끝나더라도
이미 획득한 탑 층수, 재질, 외형, 완성 구간은 사라지지 않는다.

---

# 3. 퍼즐 시스템

## 3.1 기본 규칙

- 보드: 8×8
- 블록: 3개씩 제공
- 제공된 3개를 모두 사용하면 다음 3개 제공
- 빈칸에만 배치 가능
- 배치 후 이동 불가
- 블록 회전 불가
- 가로 또는 세로 한 줄의 모든 칸이 채워지면 완성
- 제거 후 나머지 블록은 낙하하거나 이동하지 않음
- 시간 제한 없음
- 퍼즐은 오프라인 플레이를 기본으로 설계

---

# 4. 수동/자동 클리어

## 4.1 기본값

최초 실행 기본값:

> **자동 클리어 OFF = 수동 클리어**

이후에는 이용자가 마지막으로 선택한 클리어 방식을 기억한다.

---

## 4.2 수동 클리어

줄을 완성해도 즉시 사라지지 않는다.

완성된 줄은 보드에 그대로 남고,
이용자가 `[N줄 클리어]` 버튼을 누르면
현재 완성된 모든 줄을 한 번에 제거한다.

완성된 줄은 보드 공간을 계속 차지하지만,
다른 가로/세로 줄을 추가로 완성하는 데 활용될 수 있다.

특정 줄만 골라 제거하는 기능은 넣지 않는다.

완성 줄이 0개면 버튼을 비활성화한다. 배치·클리어·전환 확인창은 동시에 실행하지 않는다.
교차 줄과 보상 처리 순서는 35절을 따른다.

---

## 4.3 자동 클리어

자동 클리어 ON 상태에서는
블록 배치로 완성된 줄을 즉시 제거한다.

추가 버튼 입력은 없다.

---

## 4.4 게임 중 ON/OFF 전환

이용자는 게임 중 언제든 자동 클리어 ON/OFF를 변경할 수 있다.

### 수동 → 자동 / 대기 줄 없음
즉시 전환

안내:
`자동 클리어를 켰어요.`

### 자동 → 수동
즉시 전환

안내:
`수동 클리어로 바꿨어요. 완성된 줄은 직접 지워 주세요.`

### 수동 → 자동 / 완성된 줄 대기 중

확인창 표시:

> 자동 클리어로 바꿀까요?  
> 완성된 N줄을 지금 지우고,
> 이후 완성되는 줄은 자동으로 지웁니다.  
> 이번 클리어: +XXX점

버튼:
- 수동 유지
- 지우고 자동 전환

확정 시:
1. 대기 줄 일괄 제거
2. 정상 점수 지급
3. 자동 클리어 ON

취소 시:
아무 변화 없음

# 5. 퍼즐 점수

## 5.1 배치 점수

새롭게 채운 칸:

> **1칸 = 1점**

예:
4칸 블록 배치 = +4점

---

## 5.2 클리어 점수

공식:

> 클리어 점수 = 제거한 줄 수 × 100 × 동시 클리어 배율

| 한 번에 제거한 줄 수 | 배율 | 점수 |
|---|---:|---:|
| 1줄 | ×1.0 | 100 |
| 2줄 | ×1.2 | 240 |
| 3줄 | ×1.4 | 420 |
| 4줄 | ×1.6 | 640 |
| 5줄 이상 | ×1.6 유지 | 줄당 160점 |

자동/수동은 동일한 점수 산식을 사용한다.

수동 버튼을 눌렀다는 이유로 별도 보너스를 주지 않는다.

수동은 즉시 지우거나 보류하는 선택이 가능하므로 자동보다 가능한 전략의 범위가 넓다.
동일 산식은 실제 점수·분당 제거 줄 수·해금 시간의 동등성을 뜻하지 않는다. 모드별 결과 분포를 실측한다.
최고점은 기존 단일 기록을 유지하고 판 중 모드 전환을 허용한다. 모드별 순위를 새로 만들지 않는다.

# 6. 게임오버 규칙

게임오버는 단순히 `현재 블록을 놓을 수 없음`이 아니라
`클리어를 통해서도 진행할 수 없음`을 기준으로 판단한다.

### 배치 가능 블록 존재
계속 진행

### 배치 가능한 블록 없음 + 완성된 줄 대기 중
게임오버 아님

클리어 버튼 강조

### 배치 가능한 블록 없음 + 대기 줄 없음
게임 종료

남은 조각 중 **하나라도 한 곳에 합법적으로 배치할 수 있으면 계속 진행**한다.
남은 조각을 전부 놓을 수 있는 미래 순서가 있는지 미리 풀어 게임을 끝내지 않는다.
대기 줄이 있으면 실제 클리어 입력 후 보드를 갱신하고 다시 판정한다.
마지막 조각 사용 시 새 묶음을 지급한 다음 판정한다. 연출 중의 임시 상태로 판정하지 않는다.

# 7. 성장 시스템

## 7.1 성장 목표

퍼즐의 결과를 단순 점수로 끝내지 않고
이용자 소유의 영구적인 탑으로 변환한다.

핵심 성장축:

1. 탑 높이
2. 건축 재질
3. 외형 파츠
4. 10층 구간 완성
5. 대표 구간
6. 다른 이용자와의 비교

---

# 8. 탑 높이

## 기본 환산

> **퍼즐에서 실제 제거한 1줄 = 탑 1층**

| 클리어 | 탑 성장 |
|---|---:|
| 1줄 | +1층 |
| 2줄 | +2층 |
| 3줄 | +3층 |
| 4줄 | +4층 |
| 5줄 | +5층 |

동시에 많이 지웠다는 이유로 탑 높이 배율을 추가하지 않는다.

이유:

퍼즐 점수에서 이미 동시 클리어 보너스를 제공하므로
탑 높이는 가장 직관적인 누적 성장값으로 유지한다.

---

# 9. 재질 해금

재질은 소모 재료가 아니다.

한 번 해금하면 계속 사용할 수 있는
`건축 스타일`이다.

재질에 능력치 차이는 없다.

## 기본 계열

- 목재
- 벽돌
- 금속·유리
- 크리스털

아트 표현은 최종 Visual Bible에서 구체화한다.

---

# 10. 재질 해금 방식

재질은 두 가지 경로를 제공한다.

> **동시 클리어 = 빠른 해금 경로**
>
> **누적 플레이 = 느리지만 확실한 대체 경로**

예시:

| 재질 | 빠른 해금 | 누적 대체 해금 |
|---|---|---|
| 목재 | 기본 제공 | 기본 제공 |
| 벽돌 | 2줄 이상 동시 클리어 1회 | 누적 30줄 |
| 금속·유리 | 3줄 이상 동시 클리어 1회 | 누적 100줄 |
| 크리스털 | 4줄 이상 동시 클리어 1회 | 누적 250줄 |

수치는 초기 밸런스 가안이다.

목적:
- 자동/수동 선택 자유 유지
- 특정 외형을 얻기 위해 수동 조작을 강요하지 않음
- 숙련 이용자는 도전으로 더 빠르게 해금 가능

---

# 11. 재질 발전

재질 발전의 빠른 경로는 `동시 클리어 발생 횟수`가 아니라
`조건을 충족하며 실제로 제거한 줄 수`를 기준으로 계산한다.

## 예시

### 벽돌 진행도
2줄 이상 동시 클리어에서 제거한 줄 수

- 2줄 클리어 → +2
- 4줄 클리어 → +4

### 금속·유리 진행도
3줄 이상 동시 클리어에서 제거한 줄 수

- 3줄 → +3
- 4줄 → +4

### 크리스털 진행도
4줄 이상 동시 클리어에서 제거한 줄 수

- 4줄 → +4
- 5줄 → +5

상위 성과는 하위 재질 진행에도 반영한다.
진행도는 재질이 잠겨 있어도 첫 플레이부터 누적하며 해금 시 초기화하지 않는다.
해금 조건을 충족한 바로 그 클리어도 포함한다. 장착 재질·스킨은 집계에 영향을 주지 않는다.
외형 파츠에도 누적 줄 수 대체 해금 경로를 둔다. 세부 조건은 성장 v0.3의 8절을 따른다.

예:

4줄 동시 클리어

- 벽돌 +4
- 금속·유리 +4
- 크리스털 +4

큰 클리어가 작은 클리어보다 성장에서 불리해지는 문제를 방지한다.

# 13. 연속 성과

연속 성과는 핵심 성장 조건으로 사용하지 않는다.

## 정의

블록 배치 직전에는 미완성이었고 배치 직후 완성된 줄이 있으면 해당 묶음의 성공 여부를 기록한다.
기존 대기 줄을 유지하거나 클리어 버튼만 누르는 행위는 새로운 완성으로 세지 않는다.
3개 묶음을 모두 소진할 때 성공 여부를 한 번 정산한다. 성공이면 연속 +1, 실패면 0으로 초기화한다.
묶음 도중 게임오버 시 미완료 묶음은 정산하지 않고 현재 연속을 끝낸다. 최고 기록은 유지한다.
자동 모드에서도 제거 전에 새 완성을 감지한다. 현재 묶음 ID·성공 여부·연속 수를 저장한다.

## 역할

연속 성과는 선택형 보조 목표다.

보상 예:

- 외벽 패턴
- 조명
- 깃발
- 프로필 배지
- 대표 구간 장식
- 기록 표시

독점 핵심 재질을 연속 성과에 묶지 않는다.

유사 장식은 누적 플레이를 통해서도 얻을 수 있게 설계한다.

---

# 14. 10층 구간

## 핵심 원칙

> **탑 10층 = 하나의 건축 완성 단위**

예:

- 1~10층 = 구간 1
- 11~20층 = 구간 2
- 21~30층 = 구간 3

무한히 숫자만 증가하는 탑이 아니라
이용자가 작은 완성을 반복하도록 한다.

---

# 15. 구간 완성 경험

10층 완성 시:

1. 구간 완성 안내
2. 완성 전/후 비교
3. 새 구간의 외형 확인
4. 해금한 재질/파츠 적용 가능
5. 탑 전체에 새 구간이 결합되는 연출
6. 대표 구간 지정 가능

퍼즐 진행 중에는 건축 편집을 강요하지 않는다.

표시는 간단하게:

- `+3층`
- `다음 구간까지 2층`
- `벽돌 진행 +4`

정도로 제한한다.

---

# 16. 탑 편집

- 외벽
- 창문
- 난간
- 테라스
- 패턴
- 조명
- 상단 마감

## 편의 기능

### 전체 적용
같은 스타일을 여러 구간에 일괄 적용

### 스타일 복사
특정 구간 디자인을 다른 구간에 복사

### 구간 점프
10층 단위 이동

### 최근 편집
마지막 편집 구간 바로가기

### 재질 필터
특정 재질 구간만 보기

### 대표 구간
가장 마음에 드는 10층을 대표 작품으로 지정

# 17. 탑 감상

두 가지 뷰를 제공한다.

## 전체 탑 뷰

목적:

- 총 높이 체감
- 전체 실루엣
- 장기 성장 확인
- 다른 이용자와 높이 비교

표시:

- 총 층수
- 최고 점수
- 대표 구간
- 주요 건축 스타일

## 구간 뷰

목적:

# 35. 퍼즐 판정과 저장 계약 — v0.4 보완

## 35.1 한 번의 클리어

클리어 직전 보드에서 완성 가로줄 R과 세로줄 C를 동시에 구한다.
줄 수는 `N = |R| + |C|`, 제거 셀은 두 집합의 합집합이다. 교차 셀은 한 번만 제거한다.
가로·세로 각 1줄의 교차는 15셀 제거, 2줄 보상(+240점, +2층)이다.
8×8 전체가 찬 상태의 경계값은 16줄, 64셀 제거, +2,560점, +16층이다.
점수 예시는 클리어 점수이며 배치 점수는 별도다. N=0이면 보상을 지급하지 않는다.

## 35.2 상태 갱신 순서

1. 입력 시점에 합법 배치인지 검사하고 조각 소진·보드·배치 점수를 갱신한다.
2. 새 완성 줄을 감지하여 현재 묶음 성공 여부를 기록한다.
3. 자동 모드면 완성 줄 전체를 제거하고 점수·성장을 한 사건으로 반영한다. 수동은 대기 상태를 유지한다.
4. 묶음이 소진되었으면 연속 성과를 정산하고 다음 3개를 지급한다.
5. 최종 보드·현재 조각으로 6절의 진행/클리어 유도/게임오버를 판정한다.
6. 논리 상태를 안전하게 저장한 후 피드백을 재생한다. 연출 종료 콜백에서 보상을 지급하지 않는다.

수동 클리어도 3→5→6 순서로 처리한다(조각 묶음은 소진되지 않음).
수동→자동 확인은 대기 줄 클리어와 모드 변경을 한 사건으로 저장한다.
확인창이 열리면 보드 입력을 잠그고, 확정 직전에 줄 수와 표시 보상을 재검사한다.
드래그 중 토글 입력은 드래그를 취소한 뒤 처리한다. 취소 드래그에는 점수를 주지 않는다.

## 35.3 저장·복구

- 배치/클리어/묶음 공급/편집 확정 시 저장한다. 백그라운드 알림에만 의존하지 않는다.
- 저장 스키마 버전, 세션 ID, 마지막 처리 사건 ID, 난수 상태/공급 위치, 묶음 ID와 잔여 조각을 포함한다.
- 저장 구조 변경에는 구버전→신버전 변환 규칙과 실제 구버전 파일 복원 검증을 포함한다. 변환 실패/지원하지 않는 미래 버전은 원본을 보존하고 호환 문제를 알린다.
- 보드·점수·층수·진행도·해금·구간 완성은 같은 사건의 전부 또는 전무로 복원한다.
- 임시 파일 검증 후 교체하고 이전 정상 저장을 백업한다. 중복 사건 재처리는 보상을 추가하지 않는다.
- 대기 줄은 복원 보드에서 재계산한다. 손상 파일은 백업 복구를 시도하고 실패 시 사용자에게 복구 불가를 알린다. 조용히 초기화하지 않는다.
- 미저장 사건은 완료로 표시하지 않는다. 저장 실패 시 진행을 잠시 멈추고 재시도를 안내한다.
- 연출 도중 종료되어도 저장된 보상은 유지한다. 복귀 시 미완료 연출은 생략하거나 짧게 요약한다.
- ‘영구 성장’은 게임오버/새 판에서 초기화되지 않는다는 뜻이다. 앱 삭제·기기 변경 복구는 클라우드 도입 전 보장하지 않는다.

## 35.4 구현 검증 사례

| 조건/행동 | 기대 결과 |
|---|---|
| 잔여 조각 A는 배치 가능, B는 불가 | 게임 계속 |
| 모든 잔여 조각 배치 불가, 완성 줄 있음 | 클리어 버튼 유도, 종료 금지 |
| 클리어 후에도 모든 조각 배치 불가, 대기 줄 없음 | 종료, 이미 획득한 성장 유지 |
| 묶음 마지막 조각 사용 | 새 묶음 공급 후 판정, 빈 트레이를 게임오버로 오인하지 않음 |
| 가로/세로 교차 또는 전체 64셀 완성 | 각각 2줄/16줄 보상, 중복 셀 제거 없음 |
| 클리어 버튼 연타·토글 동시 입력 | 단일 사건 처리, 보상 중복 없음 |
| 자동 전환 확인 취소/확정 | 취소는 무변화, 확정은 표시한 보상 1회 + 자동 ON |
| 클리어 저장 전/후 각각 강제 종료 | 이전 전체 상태 또는 다음 전체 상태; 보드만 복구·성장만 중복 금지 |
| 앱 재실행 반복 | 새 묶음 재추첨·동일 보상 재지급 없음 |
| 이전 대기 줄을 다음 묶음에 계속 유지 | 새로운 완성으로 집계하지 않음 |
| 같은 위치의 줄을 지운 후 다시 완성 | 새 완성으로 집계 |
| 구버전 저장을 업데이트된 앱에서 읽기 | 변환 후 보드·점수·층수·해금·편집 유지; 실패 시 원본 보존 |

## 35.5 재현용 데이터 계약

Phase 1부터 규칙 계산과 UI/연출을 분리하고 공급 규칙 버전·시드/난수 상태로 같은 입력의 결과를 재현한다.
진단용 사건은 배치(묶음·슬롯·좌표), 수동 클리어, 모드 전환 확정으로 구분하고 사건 순서를 기록한다.
자동 클리어는 배치에서 파생시키므로 재생 중 별도 사건으로 중복 실행하지 않는다.
재현 로그는 시작 상태 스냅샷과 규칙 버전을 함께 보존한다. 보관 건수/용량을 제한하고 저장 주기를 정하며 영구 무제한 누적하지 않는다.
보관 경계에서 새 스냅샷을 생성해야 이전 사건을 잘라도 재생할 수 있다. 자동 외부 전송은 이 규칙에 포함하지 않는다.
같은 시작 상태/공급 규칙/행동을 재생했을 때 최종 보드·점수·층수·해금 결과가 일치해야 한다.
로컬 로그의 재현 가능성만으로 행동 시각·사용자 신원·부정 사용을 증명하지는 못한다. 공개 기록 검증은 37.2절에서 별도로 설계한다.

# 36. 개발 범위와 검증 관문

30절의 Phase 번호를 모든 문서에서 공통으로 사용한다. 아래는 프로토타입 범위와 통과 조건이며 출시 약속이 아니다.

| 단계 | 최소 구현 | 다음 단계 진입 조건 |
|---|---|---|
| Phase 1 퍼즐 | 기본 B 스킨, 배치/수동·자동/저장; 임시 층수 계기 | 35.4 사례와 35.5 재생 검증 통과, 첫 수동 클리어와 막힘 해소를 설명 없이 수행 가능한지 관찰 |
| Phase 2 성장 | 4재질 기본 외벽, 10층 완성, 1개 파츠의 이중 해금 경로 | 첫 30층까지 모드별 소요시간·자발적 탑 확인·해금 경로 이해를 기록 |
| Phase 3 건축 | 고정 카메라, 외벽/창 프리셋, 부분 구간, 대표 구간, 구간 점프 | 30/300/3,000층에서 이음새·가독성·기기 메모리·프레임 시간 확인 |
| Phase 4 온라인 | 검증된 주간 기록, 다른 탑 보기 | 계정·중복 업로드·오프라인 정책·주차 경계·동기화 충돌 규격 및 검증 구현 |
| Phase 5 확장 | 파츠/스타일 경쟁 등 수요 기반 확장 | 방문/편집 수요 확인 후 범위 선택 |

C 스킨의 미리보기는 시각 검증에 포함한다. 실제 유료 판매는 구매/복원 흐름 검증 이후 별도 출시 범위로 정한다.
대량 파츠 제작, 전체 적용/복사 고도화, 연속 성과 장식은 핵심 성장 검증 후 확장한다.

**차별점 검증용 최소 프로토타입은 Phase 1 + Phase 2의 최소 탑 표현**이다.
퍼즐만 완성한 상태로 성장 재미를 판정하지 않는다. 층/구간 카운터, 목재 임시 탑 화면, 구간 완성 토스트를 먼저 연결한 뒤 재질/파츠 검증으로 확장한다.

## 36.1 블록 공급 명세 — Phase 1 전에 채울 항목

조각 카탈로그는 고유 ID·점유 셀 좌표·고정 방향으로 정의한다. 회전 입력은 없고 회전된 모양을 별도 조각으로 공급할지는 명시한다.
카탈로그 버전, 추첨 가중치, 중복 허용, 보드 의존 보정, 시작 묶음, 난수 시드/상태를 하나의 공급 규칙으로 기록한다.
동일 조건 비교에는 동일 공급 규칙과 시드를 사용한다. 스킨 구매·모드 전환 때문에 재추첨하지 않는다.
‘항상 풀리는 묶음’과 강제 실패 설계는 미채택이다. 보정 유무·확률·게임오버 빈도 목표는 실험 후 결정한다.
배치 가능한 조각을 보장하는 공급안을 실험할 경우, 검사 기준을 현재 보드로 할지 대기 줄 제거 후 가상 보드로 할지 명세한다.
전자는 대기 줄을 보류해 공급을 쉽게 유도할 수 있는지, 후자는 실제 클리어 전에는 놓을 수 없는 조각을 받는 상황을 어떻게 안내할지 검증한다.
플레이 중 취소/화면 전환/복귀는 제공된 조각을 바꾸지 않는다.

## 36.2 첫 30층 검증

- 0~10층: 배치→줄 완성→수동 클리어→영구 층수의 관계를 안내한다. 첫 안내 이후 강제 손동작 지시는 줄인다.
- 10층: 기본 목재 구간을 자동 완성한다. ‘계속 퍼즐’과 ‘탑 보기’를 제공하며 편집은 선택이다.
- 11~20층: 자동/수동 전환을 이해하고 해금 목표의 두 경로를 볼 수 있게 한다.
- 21~30층: 새 구간을 직접 다르게 꾸미거나 대표 구간을 선택할 기회를 제공한다.
- 실패/새 판은 층수를 유지한다. 첫 30층을 한 판 안에 달성해야 한다는 조건은 없다.

초기 관찰 가안: 6~10명에게 모드 체험 순서를 교차 배정하고 첫 클리어, 첫 10/30층 도달 시간, 오배치, 자발적 탑 방문, 재플레이 선택을 기록한다.
도달 실패자/중도 이탈자도 포함한다. 작은 표본을 통계적 성공 판정으로 포장하지 않는다.
반복되는 규칙 오해가 있으면 Phase 1 UX를 수정하고, 층수를 확인/꾸밀 이유를 찾지 못하면 Phase 2 보상을 재검토한다.
수집 항목·보관·전송 방식과 정량 성공 기준은 테스트 계획에서 정한다. 관찰 전 임의의 리텐션 수치를 확정하지 않는다.

# 37. 탑 표현 및 온라인 선행 결정

## 37.1 프리렌더 모듈

- 4재질 × 다수 창문 × 난간 × 테라스 × 조명 × 지붕 전체 조합을 개별 이미지로 만들지 않는다.
- 초기에는 재질별 외벽/창 프리셋과 별도 상단 마감으로 제한하고, 레이어 합성 가능성은 이음새 샘플로 확인한다.
- 카메라 투영/각도, 바닥·상단 앵커, 층 높이, 가로 폭, 광원 방향, 여백, 그림자, 렌더 해상도를 공통 규격으로 고정한다.
- 직교 투영을 우선 검증 후보로 둔다. 1층 타일/슬롯 레이어 합성과 10층 프리셋을 같은 샘플로 비교해 이음새·그림자·자산 수를 확인한다. 각도·층당 픽셀 수와 레이어 간 그림자 처리 방식은 아트 규격에서 정한다.
- 지붕/첨탑은 실제 최상단 전용이다. 중간 구간의 마감은 위 구간과 결합 가능한 띠장으로 구분한다.
- 부분 구간은 확보한 층수만 표현한다. 9층을 완성된 10층으로 표시하지 않는다. 세부 재사용 방식은 1~9층 샘플로 정한다.
- 부분 구간을 비계로 표현하는 안은 비교 후보이며 건설 대기시간을 뜻하지 않는다. 기본안은 확보 층수 표시다.
- 대표 구간 단독 화면의 기본 마감은 구간 경계 마감이다. 실제 탑 최상단 전용 첨탑을 모든 출품 구간에 복제하지 않는다.
- 화면 근처 구간만 로드/표시하고 전체 뷰는 축약 실루엣과 총 층수, 구간 점프를 사용한다.
- 프리렌더가 자동으로 저메모리를 보장하지 않는다. 목표 기기·텍스처 크기·메모리·프레임 예산은 Phase 3 전 실측 후 고정한다.
- 새 구간은 기본 목재 프리셋을 사용한다. 해금/재질 변경으로 기존 구간을 자동 덮어쓰지 않는다.

## 37.2 온라인 기록

오프라인 성과는 개인 탑에 보존한다. 단말 저장의 누적값을 검증 없이 공개 랭킹에 올리지 않는다.
Phase 1~3은 계정·공개 랭킹을 필수 의존성으로 삼지 않는다.
Phase 4 전에는 아래 항목의 단일 정책과 예외 처리를 확정한다.

| 항목 | 결정할 내용 / 통과 조건 |
|---|---|
| 주차 | 서버 기준 시간대·주 시작·마감·지연 업로드 귀속; 마감 전후 같은 사건이 두 주에 집계되지 않음 |
| 오프라인 제출 | 서버 발급 시드/행동 검증 방식과 유효기간, 미검증 기록 처리; 개인 성장 유지 |
| 중복·변조 | 사건 ID 재전송, 시계 조작, 파일 편집 대응; 로컬 체크섬은 부정 방지 증거로 취급하지 않음 |
| 여러 기기 | 계정 귀속, 충돌 해결, 탑 편집 병합/선택; 누적값 단순 합산 금지 |
| 순위/보상 | 동률·플레이 시간 편향·부정 기록 정정 및 보상 회수 범위; 초기에는 보상 경쟁 확대 보류 |

서버 수신 시각만으로 주차를 정하면 오래 모아 둔 오프라인 기록을 특정 주에 제출할 수 있다.
따라서 수신 주차 채택 여부는 서버 발급 과제/시드의 유효기간, 지연 제출 한도, 재생 검증과 함께 결정한다.
기기 시간 변경, 같은 로그 재전송, 지난 주 기록을 모아 제출하는 사례를 모두 검증해야 한다.

| 총 제거 줄 수 | 탑 총 층수와 같은 개인 성장 누적값; 파츠 대체 해금 기준 |
| 구간 | 10층짜리 건축 완성/편집 단위 |
| 경계 마감 | 다음 구간과 결합 가능한 구간 상단 형태 |
| 최상단 마감 | 실제 탑 맨 위의 첨탑/지붕; 구간 경계 마감과 별도 |

v0.3→v0.4는 규칙 경계/저장 계약/개발 관문을 보완한 개정이다.
Claude Code의 독립 검토에서 마이그레이션·재현용 데이터·최소 탑 검증·시각 상태 공통화 의견을 추가 반영했다.
프레스티지 파츠 독점, 보장형 블록 공급, 빠른 해금 횟수 상향, 기본 스타일 상속은 채택하지 않았다.
상세 근거와 미결정 항목은 [검토·결정 기록](Blocktower_Redteam_Review_2026-09-20.md)을 따른다.
