# Phase 2-A: 목재·벽돌 외벽 첫 적용

기준일: 2026-09-24. Sol이 범위 결정과 독립 검증을 맡고, 옆 창의 GPT-6 Luna가 구현과 개발 실행을 맡는다. 사람 관찰과 최신 Android 실기기 검증은 사용자 요청대로 이후에 진행한다.

## 범위

기존 `GameSession`의 `SET_SEGMENT_STYLE` 계약과 벽돌 해금 가안을 그대로 사용한다. 탑 화면에서 완성된 10층 구간을 선택해 목재 또는 해금된 벽돌 외벽을 적용한다. 미완성 구간, 잠긴 벽돌, 이미 적용한 재질은 변경하지 않으며, 실패 시 저장된 상태를 다시 표시한다. 새 구간의 기본 재질은 목재이고 대표 구간 설정과 서로 독립이다.

벽돌은 기존 목재 모듈과 같은 카메라·광원·640×480 캔버스·층 간격·앵커를 쓰는 편집 가능한 3D 원본에서 프리렌더한다. 외벽, 창, 구조선이 작은 화면에서도 목재와 구별되어야 하며 목재와 벽돌이 이어지는 경계, 첫/중간/최상단 10층 구간, 1~9층 부분 구간의 층수 표현을 유지한다. 단순 색상 tint를 최종 벽돌 아트로 간주하지 않는다.

금속·유리와 크리스털 외벽, 벽돌 파츠 장착, C 장식, 밸런스 수치 변경은 이번 범위 밖이다. 해당 재질 해금 사실은 기존 UI에서 계속 확인할 수 있다. 아직 그림이 없는 재질은 탑 외벽 선택지로 제공하지 않는다. 기존 저장에 해당 스타일 값이 있으면 데이터 손실 없이 명시적인 미제작 표시와 안전한 그림 대체를 제공한다.

## 완료 조건

1. 실제 탑 화면에서 목재·벽돌 선택, 잠금/완성 구간 상태, 현재 적용 재질이 읽히며 320×568 안전 영역과 큰 글씨에서도 조작 버튼이 겹치지 않는다.
2. `GameSession` 결과가 성공한 뒤에만 외형이 바뀐다. 저장 후 재실행해 대표 구간과 구간별 재질이 유지되고 다른 구간의 스타일은 바뀌지 않는다. 목재 재선택은 sparse `segment_styles` 항목을 제거한다. 화면에서 탐색 중인 구간 번호는 영구 저장 대상이 아니다.
3. 같은 규격의 벽돌 모듈 원본과 PNG가 재생성 가능하고 에셋 출처·제작 방식이 기록된다. 목재↔벽돌 이음새를 실제 Godot 캡처로 검토한다.
4. 고정 Godot 4.7.2/GUT 9.7.1 전체 검사에서 파서 오류·실패·pending·0건 발견이 없다. Sol이 코드 경계, 저장 결과와 Windows 실제 화면을 독립 확인한다.

이번 결과는 제한된 외벽 편집 구현이다. 사람의 이해도, 반복 피로, 실제 손가락 조작, Android 성능 판정은 포함하지 않는다.

## 구현과 독립 검증 결과

GPT-6 Luna는 기존 `SET_SEGMENT_STYLE` 저장 계약에 탑 화면의 목재·벽돌 선택을 연결하고, 같은 원본 규격의 벽돌 층 4종과 재생성 스크립트를 추가했다. 완성된 10층 구간만 편집할 수 있으며 잠긴 벽돌은 선택할 수 없다. 잠금 안내는 **동시 2줄 또는 누적 30층**으로 표시한다. 금속·크리스털 저장값은 지우지 않고 미제작 상태를 알리며 목재 그림으로 대체한다. 제작 원본·실행 결과·출처는 [Luna 구현 보고서](../../tools/out/phase2a_brick_facade/report.json)에 기록했다.

Sol은 최종 코드로 고정 Godot 4.7.2/GUT 9.7.1 전체 검사를 독립 재실행했다. **9개 스위트, 115개 테스트, 3,272개 단언, 실패·오류·pending 0개**였다. 별도 출력 폴더의 [탑 화면 5개 시나리오](../../tools/out/phase2a_sol_verify_20260924/summary.json)에서 저장 재개·구간별 독립성, 잠금/미완성 상태, 320×568 큰 글씨·상하 24px 안전 영역, 412×915 벽돌 화면 등 **58개 점검이 모두 통과**했다. Sol은 [잠긴 상태](../../tools/out/phase2a_sol_verify_20260924/inset_text_tower_locked_320x568.png)와 [벽돌 탑](../../tools/out/phase2a_sol_verify_20260924/tower_brick_412x915.png)을 직접 확인했다.

목재↔벽돌 경계는 Godot 360×800에서 [목재 위·벽돌 아래](../../tools/out/phase2a_seam_sol_verify_20260924/wood_over_brick.png)와 [벽돌 위·목재 아래](../../tools/out/phase2a_seam_sol_verify_20260924/brick_over_wood.png)를 모두 확인했다. 공통 640×480 캔버스, (320,240) 앵커와 106.468px 층 간격을 사용하며, 두 방향에서 눈에 띄는 틈이나 밝은 알파 테두리가 없었다. Sol의 별도 재생성 PNG는 Luna 출력과 두 장 모두 SHA-256이 일치했다. 이 검사는 **2층 경계 샘플**이며 전체 탑 조립의 승인으로 확대하지 않는다.

새 벽돌 렌더러·편집 장면·PNG와 제작 출처를 [아트 원본 안내](../../art_source/visual_bible/README.md)와 [에셋 등록부](../../art_source/visual_bible/manifest.json)에 추가했다. Sol이 등록부의 **76개 경로**를 독립 대조한 결과 누락·크기·SHA-256 불일치가 없었다.

320×568에서는 10층 전체를 보여 주는 탑 그림 자체가 작다. 현재 재질은 글자와 색으로도 구별되지만, 세부 창·줄눈의 실제 기기 가독성은 후속 관찰 대상이다. 이번 작업으로 G2의 사람 관찰 선행 조건이나 4재질 전체 아트 관문을 통과했다고 표시하지 않는다.
