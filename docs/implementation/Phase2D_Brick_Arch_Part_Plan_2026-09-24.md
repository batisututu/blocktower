# Phase 2-D: 벽돌 아치 창문 최소 파츠

기준일: 2026-09-24. Sol이 계획·독립 검증을 맡고 옆 창의 GPT-6 Luna가 코드·에셋 구현을 맡는다. 사용자 요청대로 사람 관찰과 최신 Android 실기기 검증은 이후에 진행한다.

## 범위와 계약

첫 장착 파츠는 성장 기획의 `brick_arch_window`(벽돌 아치 창문) 한 종류다. 기존 `Growth.describe()`의 빠른 경로 **벽돌 진행도 10줄** 또는 누적 대체 경로 **총 60층**을 그대로 사용한다. 벽돌 기본 재질 해금도 선행 조건이다. 수치는 관찰 전 가안이며 이번에 조정하지 않는다.

완성된 구간이 현재 벽돌 외벽일 때 파츠를 선택하거나 해제한다. 선택된 구간의 벽돌 창문은 실제 아치형 구조로 바뀌고, 다른 구간은 그대로다. 재질을 목재·금속·유리·크리스털로 바꾸면 파츠 선택 기록은 보존하되 그림에서는 숨긴다. 벽돌로 돌아오면 다시 표시한다. 신규 구간에는 파츠를 자동 장착하지 않는다. 저장 성공 후에만 기록과 그림이 바뀌고 실패·같은 값·잠김·미완성·잘못된 재질은 변경을 거부한다.

저장 형식은 타입이 명시된 **`bt_session_v2`**로 올리고 `growth.segment_parts`를 추가한다. 값은 완성 구간의 정규 십진수 ID→정렬된 고유 파츠 ID 배열이며, 이 범위에서 허용 ID는 `brick_arch_window` 하나다. 빈 배열은 저장하지 않는다. 기존 `bt_session_v1` 파일은 체크섬·정규 JSON·기존 필드·기존 상태 검증을 통과한 뒤 메모리에서 `segment_parts={}`를 더해 v2로 읽는다. 읽기만으로 파일·revision·event ID를 변경하지 않고, 이후 성공한 일반 액션이 v2 상태를 원자적으로 저장한다. 기존 두 세대 복구·경합·중단 정책을 유지한다. 외부 봉투 `bt_save_envelope_v1`은 전송 형식이 같으면 유지할 수 있다. 규칙 수치가 그대로라면 `bt_rules_v1`도 유지한다. 알 수 없는 미래 버전과 손상된 v1/v2는 묵시적으로 고치지 않는다.

코어 액션 `SET_SEGMENT_PART`는 `segment`, `part`, `enabled:bool`을 받고, 장착에는 현재 벽돌 외벽과 파츠 해금이 필요하다. 해제는 다른 재질에 숨겨 둔 기록에도 허용한다. 저장된 파츠는 해금된 완성 구간의 알려진 ID여야 하고 중복·비정규 키·빈 값은 거부한다. 커밋이 성공한 뒤 `TOWER_CHANGED`를 반환하며 공급 RNG·점수·층수·대표 구간을 건드리지 않는다.

기존 외벽 선택 시트 안에서 벽돌 아치 창문의 잠김·해금·장착·숨김 상태와 **진행도 10줄 또는 누적 60층**을 읽을 수 있게 한다. 320×568 큰 글씨·상하 24px 안전 영역에서 스크롤 가능한 48px 선택지와 고정 닫기 버튼, 뒤로가기·포커스 복귀를 유지한다. 파츠 설명이 네 기본 외벽 선택을 가리지 않도록 간결하게 표시한다.

아트는 벽돌과 공통 카메라·광원, 640×480 캔버스, (320,240) 앵커, 106.4683685px 층 간격을 사용하는 편집 가능한 Godot 3D 원본 및 투명 PNG 네 층 모듈로 만든다. 벽돌 기본 창문의 단순 tint가 아니라 뚜렷한 아치 구조여야 한다. 에셋 등록부에 재생성 명령·출처·크기·SHA-256을 기록한다.

## 완료 조건

1. 기존 v1 실제 저장 두 세대와 샘플이 손실 없이 재개된다. 무조작 재개는 파일 바이트·revision을 바꾸지 않으며, 첫 성공 커밋 후 v2가 저장·재개된다. 중단·손상·미지원 버전의 기존 오류 경계를 유지한다.
2. 빠른/누적 파츠 해금, 잠김·미완성·비벽돌·중복 장착·해제·저장 실패, 재질 전환 중 숨김/복원, 구간 독립성을 코어와 실제 버튼 입력으로 확인한다.
3. Windows 탑 화면에서 기본 벽돌과 아치 창문 변형이 320px에서도 구별된다. 320×568 큰 글씨·24px 안전 영역 및 360×800/412×915에서 선택지 48px 전체가 스크롤 끝에 드러나고 닫기 버튼과 겹치지 않는다. 아치↔기본 벽돌 2층 양방향 경계와 기존 재질 경계를 샘플로 확인한다.
4. 고정 Godot 4.7.2/GUT 9.7.1 전체 검사, 파일·프로세스 저장 복구 검사와 Sol 별도 Windows 캡처·해시 대조에서 파서 오류·실패·pending·0건 발견이 없다.

이 작업은 첫 파츠 한 종류의 기능·저장 경로다. 다른 벽돌 파츠, 금속·유리/크리스털 파츠, 첨탑·지붕 편집, 전체 탑 합성, 밸런스 확정, 사람 관찰과 Android 최신 빌드·실기기 검증은 포함하지 않는다. Phase 2 확대와 G2 관문 전체 통과로 표시하지 않는다.

## 구현·검증 결과 (2026-09-24)

옆 창 GPT-6 Luna가 `brick_arch_window`의 `SET_SEGMENT_PART` 액션, 구간별 파츠 저장·휴면/복원, 외벽 선택 시트, 원본 Godot 3D 장면 4개와 투명 PNG 4개를 구현했다. 새 세션은 `bt_session_v2`를 저장한다. 실제 v1 저장 샘플은 기존 체크섬·정규 형식·상태 검사를 거친 뒤 읽기 전용으로 v2 상태에 전환되며, 첫 성공 액션에서만 v2 세대를 쓴다. 아치 창문을 장착한 구간은 작은 화면의 탑 캡션에도 `현재 벽돌 · 아치 창문`으로 표시한다.

Sol이 Luna 작업 종료 후 고정 Godot 4.7.2/GUT 9.7.1 전체 검사를 **별도로 재실행**했다. 9개 스위트, **125개 테스트·3,419개 단언**, 실패·오류·보류 0개였다. 저장 재시작 검사 **29개**를 재실행해 실제 v1 두 세대의 무조작 재개 바이트 보존과 첫 v2 커밋을 확인했다. Windows 네이티브 화면 **8종·147개 점검**은 Luna 실행에서 모두 통과했고, Sol은 320×568 스크롤 시트 및 320×568/412×915 탑 화면 3종을 독립 재생성했다. 아치↔기본 벽돌 **2방향** 층 경계와 과거 금속·유리 4방향·크리스털 6방향 경계도 Sol이 별도 경로에서 재생성해 모두 통과했다. 에셋 등록부 **106개 파일**의 경로·크기·SHA-256을 Sol이 다시 대조해 불일치 0개를 확인했다.

실행 증거는 `tools/out/phase2d_brick_arch/report.json`, `tools/out/phase2d_brick_arch/native_release/summary.json`, `tools/out/phase2d_brick_arch/seams/summary.json` 및 Sol의 `tools/out/phase2d_sol_verify_20260924`, `tools/out/phase2d_sol_seams_20260924`에 있다. 프로세스 종료 검사는 Windows 파일·프로세스 경계이며 실제 전원 손실 증거가 아니다. 320×568에서는 기존 탑 축척상 아치 조형이 작아 장착 캡션으로 상태를 보강했다. 사람 관찰과 최신 Android 실기기 검증은 사용자 요청대로 이후에 진행한다.
