# Phase 2-E: 벽돌 테라스 파츠

기준일: 2026-09-24. Sol은 계획과 독립 검증, 옆 창의 GPT-6 Luna는 코드·아트·검사 구현을 맡는다. 두 창은 컨텍스트 사용률이 70%를 넘으면 10% 이하로 압축한 뒤 작업을 계속한다. 사람 관찰과 최신 Android 실기기 검증은 사용자 요청대로 이후에 진행한다.

## 범위와 State/Action/Result 계약

성장 기획의 다음 벽돌 파츠 `brick_terrace`를 추가한다. 기본 벽돌 해금 후 **벽돌 진행도 30줄 또는 누적 총 120층**이면 해금한다. 기존 `Growth.describe()` 수치를 그대로 사용한다. 완성된 구간의 현재 외벽이 벽돌일 때 `SET_SEGMENT_PART {segment, part:"brick_terrace", enabled:bool}`로 장착한다. 이미 있는 `brick_arch_window`와 독립적으로 장착·해제하며 두 파츠를 같은 구간에 함께 쓸 수 있다.

`growth.segment_parts`는 기존 `bt_session_v2`의 완성 구간 ID→정렬된 고유 파츠 ID 배열을 유지한다. 허용 ID는 이번 범위에서 `brick_arch_window`, `brick_terrace` 두 개이며 빈 항목을 저장하지 않는다. 기존 v1→v2 읽기 전용 마이그레이션과 v2 저장·복원, 파일 원자 커밋 경계를 유지한다. 저장 검증은 알 수 없는 ID·중복·비정렬·잠기거나 미완성된 구간을 거부한다. 다른 외벽으로 바뀐 구간의 파츠 기록은 보존하고 그림에서 숨긴다. 벽돌로 돌아오면 두 파츠를 복원한다. 장착 시 잠김·미완성·비벽돌은 오류, 같은 값은 `NO_CHANGE`, 커밋 실패는 상태·그림·이벤트 무변경이다. 성공하면 `TOWER_CHANGED`를 반환하고 점수·층수·대표 구간·공급 RNG는 바꾸지 않는다.

실제 탑에서 테라스는 선택 구간의 한 층에 난간·돌출 바닥이 있는 형태로 보인다. 아치 창문 장착 여부에 따른 두 합성 형태를 제공하고, 나머지 층의 아치 선택은 유지한다. 네 기본 외벽·아치 선택지는 유지하며 외벽 선택 시트에 테라스의 잠김·장착·숨김·해제 상태와 **벽돌 30줄 또는 누적 120층**을 표시한다. 선택 구간 캡션은 함께 장착한 두 파츠를 모두 읽을 수 있어야 한다.

아트는 기존 640×480, (320,240) 앵커, 106.4683685px 층 간격과 벽돌 광원·카메라를 공유하는 편집 가능한 Godot 3D 원본 및 투명 PNG로 만든다. 원본·출처·재생성 명령·크기·SHA-256을 에셋 등록부에 기록한다. 표현 방법은 Luna가 기존 렌더러 구조에 맞게 정하되, 두 파츠 동시 장착과 인접 층 경계가 자연스러워야 한다.

## 완료 조건

1. 테라스의 빠른 경로와 누적 경로, 기본 벽돌 선행 조건, 장착·해제·중복·잠김·비벽돌·미완성·저장 실패, 구간 독립성, 아치와의 양방향 공존을 코어와 실제 버튼 입력에서 확인한다.
2. v1 실제 저장 두 세대 및 기존 v2 파일을 무조작으로 재개할 때 바이트·revision이 유지된다. 첫 성공 액션 뒤의 v2 재개에서 두 파츠 배열이 정렬된 채 보존된다. 기존 손상·경합·중단 오류 경계를 유지한다.
3. Windows 네이티브 320×568 큰 글씨·24px 안전 영역과 360×800/412×915에서 모든 48px 선택지가 스크롤 끝에 드러나고 닫기 버튼과 겹치지 않는다. 선택 캡션과 테라스 실루엣이 확인된다. 기본 벽돌↔테라스 및 아치↔아치+테라스의 위아래 층 경계, 기존 재질 경계가 맞는다.
4. 고정 Godot 4.7.2/GUT 9.7.1 전체 검사, 파일·프로세스 저장 복구 검사, 별도 Windows 캡처와 에셋 해시 검증에서 파서 오류·실패·보류·0건 발견이 없다.

이번 작업은 테라스 한 파츠의 기능·아트·저장 경로다. 사람 관찰 및 최신 Android 실기기 검증은 후속 관문에 남긴다.

## 구현·검증 결과 (2026-09-24)

옆 창 GPT-6 Luna가 `brick_terrace`의 독립 장착·해제와 아치 창문 병합 그림, 외벽 선택 시트, Godot 3D 원본 4개·투명 PNG 4개를 구현했다. `bt_session_v2` 형식은 그대로 두고 파츠 ID 두 개를 정렬된 배열로 보존한다. 실제 v1 두 세대의 읽기 전용 재개, 기존 v2의 무조작 재개와 첫 성공 액션 뒤 두 파츠 복원을 확인했다.

Sol은 Luna 종료 후 고정 Godot 4.7.2/GUT 9.7.1 전체 검사를 별도로 재실행했다. **9개 스위트, 127개 테스트·3,453개 단언**, 실패·오류·보류 0개였다. 별도 프로세스 저장 재시작 검사 **33개**, Windows 네이티브 **7화면·137개 점검**을 별도 출력 경로에서 다시 통과했다. 320×568 큰 글씨의 스크롤 끝에서 테라스 48px 버튼 전체가 닫기 버튼 위에 있고, 뒤로가기와 포커스 복귀도 확인했다. 테라스 단독·아치 병합 캡처를 직접 보고, 새 테라스 **4방향**과 기존 아치/재질 **12방향** 층 경계를 재생성해 빈 겹침 행 0개를 확인했다. 에셋 등록부 **116개 파일**의 경로·크기·SHA-256도 모두 일치했다.

Luna 증거는 `tools/out/phase2e_brick_terrace/report.json`, `native_final4/summary.json`, `seams/summary.json`에 있다. Sol 재검사 출력은 `tools/out/phase2e_sol_verify_20260924`, `tools/out/phase2e_sol_seams_20260924`, 별도 저장 재시작 결과 `tools/out/w3_restart_af129f777c05/summary.json`에 있다. 기존 탑 축척 때문에 320×568에서는 테라스 조형이 매우 작아 선택 구간 캡션으로 상태를 보강했다. Windows 프로세스 종료 검사는 실제 전원 손실이나 Android 성능 검증이 아니며, 사람 관찰과 최신 Android 실기기 검증은 사용자 요청대로 이후에 진행한다.
