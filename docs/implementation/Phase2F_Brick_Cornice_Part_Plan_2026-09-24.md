# Phase 2-F: 벽돌 상단 장식 파츠

기준일: 2026-09-24. Sol은 계획·독립 검증과 상위 문서를 맡고, 옆 창의 GPT-6 Luna는 코드·아트·검사 구현을 맡는다. 두 창의 컨텍스트가 70%를 넘으면 10% 이하로 압축한 뒤 개발을 계속한다. 사람 관찰과 최신 Android 실기기 검증은 사용자 요청대로 이후에 진행한다.

## 범위와 State/Action/Result 계약

성장 기획의 다음 벽돌 파츠 `brick_cornice`(벽돌 상단 장식)를 추가한다. 기존 `Growth.describe()`의 벽돌 기본 재질 해금 후 **벽돌 진행도 60줄 또는 누적 총 200층** 조건을 그대로 사용한다. 완성된 벽돌 구간에서 `SET_SEGMENT_PART {segment, part:"brick_cornice", enabled:bool}`로 장착·해제한다. 기존 아치 창문·테라스와 각각 독립적이며 세 파츠를 같은 구간에 함께 쓸 수 있다.

`growth.segment_parts`의 기존 `bt_session_v2` 형식과 읽기 전용 v1→v2 전환을 유지한다. 허용 ID는 `brick_arch_window`, `brick_terrace`, `brick_cornice` 세 개이고, 배열은 정렬·중복 없음·빈 항목 생략이다. 저장 상태는 알려진 해금 파츠와 완성 구간만 허용한다. 장착은 벽돌 외벽과 해금이 필요하다. 다른 재질로 바꾸면 세 파츠 기록을 보존하되 해당 재질 그림에서는 숨기고, 벽돌 복귀 시 모두 되살린다. 휴면 파츠는 해제할 수 있다. 잠김·미완성·비벽돌·잘못된 ID를 거부하고, 같은 값은 `NO_CHANGE`, 커밋 실패는 상태·화면·이벤트 무변경이다. 성공 시 `TOWER_CHANGED`를 반환하고 점수·층수·대표 구간·공급 RNG는 건드리지 않는다.

상단 장식은 선택한 **완성된 벽돌 구간의 상단 마감**에 보이는 돌출 석재 띠와 반복되는 치형 장식이다. 맨 위 구간은 기존 지붕 형상을 살린 장식 지붕 마감, 그 아래 구간은 장식 수평 마감으로 구분한다. 기존 아치 창문은 층 창문에, 테라스는 구간 아래 한 층에 적용하므로 상단 장식과 그림 선택이 독립적이어야 한다. 미완성 구간·다른 재질·장착하지 않은 벽돌 구간에는 기본 마감이 남는다. 네 기본 외벽과 두 기존 파츠 선택지는 유지하고, 시트에 상단 장식의 잠김·장착·숨김·해제 상태 및 **벽돌 60줄 또는 누적 200층**을 읽기 쉽게 표시한다. 선택 구간 캡션은 세 파츠 동시 장착도 모두 알린다.

아트는 기존 공통 카메라·광원, 투명 640×480 캔버스, (320,240) 앵커와 106.4683685px 층 간격을 지키는 편집 가능한 Godot 3D 원본 및 PNG로 만든다. 장식 지붕/수평 마감 두 형태가 기본 마감과 구조적으로 달라야 하며 기존 지붕·층과 겹침 틈이 없어야 한다. 원본·재생성 명령·출처·크기·SHA-256을 에셋 등록부에 남긴다.

## 완료 조건

1. 빠른/누적 해금, 벽돌 선행 조건, 장착·해제·중복·잠김·미완성·비벽돌·저장 실패, 구간 독립성, 세 파츠 공존과 재질 전환 중 휴면/복원을 코어·실제 버튼 입력으로 확인한다.
2. 실제 v1 두 세대와 기존 v2 파일은 무조작 재개 시 바이트·revision이 유지된다. 첫 성공 커밋 뒤 세 파츠 정렬 배열이 새 프로세스에서도 보존된다. 손상·경합·중단 오류 경계를 유지한다.
3. 320×568 큰 글씨·24px 안전 영역, 360×800, 412×915에서 일곱 선택지의 48px 목표가 스크롤 끝까지 닫기 버튼과 겹치지 않는다. 상단 장식 단독 및 아치·테라스와의 병합 캡션·실제 그림이 확인된다. 지붕형/수평형 마감과 벽돌 최상층의 접합, 이전 외벽 경계가 맞는다.
4. 고정 Godot 4.7.2/GUT 9.7.1 전체 검사, 파일·프로세스 저장 복구, 별도 Windows 캡처, 층 경계와 에셋 해시 검증에서 파서 오류·실패·보류·0건 발견이 없다.

이 단계는 벽돌 상단 장식 한 파츠에 한정한다. 랜드마크 외벽, 타 재질 파츠, 전체 탑 합성, 사람 관찰과 최신 Android 실기기 검증은 후속이다.

## 구현 및 Sol 독립 검증 결과 (2026-09-24)

Luna가 `brick_cornice`를 기존 `bt_session_v2`의 세 번째 벽돌 파츠로 연결하고, 선택 구간의 맨 위 여부에 따라 수평 장식 마감 또는 장식 지붕을 사용하도록 구현했다. 아치 창문·테라스와 동시에 장착할 수 있고, 다른 재질에서는 기록을 유지한 채 숨겼다가 벽돌 복귀 시 복원한다. 해금 안내·외벽 선택지·선택 구간의 사용자 표기를 `상단 장식`으로 맞췄다. 두 파츠 조합 세 가지와 세 파츠 동시 장착의 선택 구간 문구는 실제 장착 목록으로 만든다. 기존 지붕 세 크기의 금색 깃발도 새 장식 지붕에 유지했다. 원본은 `art_source/visual_bible/render_brick_cornice.gd`와 네 Godot 장면이며 런타임 PNG 네 장을 재생성할 수 있다.

Sol이 최종 수정 후 고정 Godot 4.7.2/GUT 9.7.1 전체 검사를 다시 실행해 **130개 테스트·3,510개 단언, 실패·오류·보류 0**을 확인했다. Windows 별도 프로세스 저장 재시작은 **37/37**로, 실제 v1 읽기 전용 재개와 첫 v2 쓰기, 기존 두 파츠 및 새 세 파츠 v2의 두 세대 보존을 포함한다. 새 Windows 네이티브 캡처는 **11화면·203/203개 점검**을 통과했다. 320×568에서 아치+상단, 테라스+상단, 세 파츠 캡션과 스크롤 끝의 일곱 번째 48px 버튼을 직접 확인했다. 412×915 장식 지붕에서는 Godot 가져오기 캐시를 갱신한 뒤 깃발이 실제 게임 화면에 표시됨을 확인했다. 갱신 전/후 같은 지붕 꼭대기 영역의 금색 픽셀은 0개/34개였다.

새 상단 장식 6방향과 이전 테라스·아치·기본 외벽 16방향, 합계 **22개 층 접합 샘플**을 Sol이 다시 만들었다. 최종 깃발 이미지로 새 6방향도 재검사했다. 모든 샘플의 겹침 구간 빈 실루엣 행은 0이다. 에셋 등록부 **126개 항목**의 크기·SHA-256과 PNG 치수 **34개**가 실제 파일과 일치했다. 별도 이전 기본 화면 19종의 캡처도 통과했다. 증거는 `tools/out/phase2f_sol_final_native_20260924/summary.json`, `tools/out/w3_restart_c023eb5bdabe/summary.json`, `tools/out/phase2f_sol_final_seams_20260924/summary.json`, `tools/out/phase2f_sol_seams_20260924/`, `tools/out/phase2f_sol_fidelity_20260924/`, `tools/out/gut_unit.xml`에 있다.

GUT는 통과와 별개로 기존 orphan 경고 45개를 출력했다. 사람의 게임필 관찰, 최신 Android 빌드·설치·실기기 검증, 전체 탑 합성과 랜드마크 등 다음 파츠는 이번 결과에 포함하지 않는다.
