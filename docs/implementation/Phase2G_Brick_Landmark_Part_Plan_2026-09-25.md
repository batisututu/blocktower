# Phase 2-G: 벽돌 랜드마크형 외벽 파츠

기준일: 2026-09-25. Sol은 계획·독립 검증·상위 문서를, 기존 GPT-6 Luna 창은 코드·아트·검사 구현을 맡는다. 두 창 중 어느 쪽이든 컨텍스트가 70%를 넘기 전에 압축해 10% 이하로 만든 후 개발을 계속한다. 사람 관찰과 최신 Android 빌드·실기기 검증은 사용자 요청대로 후속이다.

## 구현 계약

성장 기획 §3의 네 번째 벽돌 파츠 `brick_landmark`를 구현한다. 벽돌 기본 재질 해금 후 **벽돌 진행도 100줄 또는 누적 총 300층**이면 해금한다. 기존 `Growth.describe()`의 가안 수치는 바꾸지 않는다. 완성된 벽돌 구간에 `SET_SEGMENT_PART {segment,part:"brick_landmark",enabled:bool}`로 장착·해제한다. 아치 창문·테라스·상단 장식과 독립적이고 네 파츠 모두 같은 구간에 공존한다.

기존 `bt_session_v2`의 `growth.segment_parts`를 유지한다. 허용 ID는 `brick_arch_window`, `brick_cornice`, `brick_landmark`, `brick_terrace` 네 개이고, 구간별 배열은 사전순·중복 없음·빈 항목 생략이다. v1 저장은 검증 후 메모리에서만 v2로 전환하고 읽기만으로 파일·revision을 바꾸지 않는다. 기존 v2 두/세 파츠 저장도 재개만으로 수정하지 않는다. 성공한 첫 행동 뒤 새 네 파츠 배열이 두 저장 세대와 새 프로세스에서 복원된다. 장착은 해금된 완성 벽돌 구간에만 허용하며 다른 재질로 변경한 동안 장착 기록은 휴면으로 보존한다. 휴면 해제는 가능하다. 잠김·미완성·비벽돌·잘못된 ID를 거부하고 동일값은 `NO_CHANGE`, 실패한 커밋은 상태·화면·이벤트를 바꾸지 않는다. 성공은 `TOWER_CHANGED`를 내고 점수·층수·대표 구간·공급 RNG를 건드리지 않는다.

## 화면과 원본 아트

랜드마크는 선택한 완성 벽돌 구간의 **중간 층에 시계면·입체 기둥/부조가 있는 랜드마크 층**으로 보인다. 단순 재색칠을 피하고 형태로 식별되게 한다. 기존 일반 벽돌층과 아치 창문층 각각에 맞는 편집 가능한 랜드마크 변형을 만들어, 아치 장착 여부에 따라 올바른 중간 층 모듈을 고른다. 테라스는 구간 아래층, 상단 장식은 지붕/수평 마감에 남아 네 파츠가 함께 보인다. 다른 구간과 비벽돌 구간, 미장착 벽돌 구간의 그림은 기존과 같다. 기존 지붕의 금색 깃발도 유지한다.

공통 카메라·광원, 투명 640×480 캔버스, (320,240) 앵커, 106.4683685px 층 간격을 그대로 쓴다. Godot 3D 원본 장면과 재생성 스크립트, 런타임 PNG, 크기·SHA-256·출처를 에셋 등록부에 기록한다. PNG를 재생성한 뒤 Godot 가져오기를 갱신하고 **실제 게임 캡처**에서 새 픽셀이 쓰이는지 확인한다.

외벽 시트는 네 기본 재질과 네 벽돌 파츠, 총 여덟 선택지를 제공한다. 랜드마크 잠김/장착/숨김/해제와 `벽돌 100줄 또는 누적 300층` 안내가 정확해야 한다. 320×568 큰 글씨·24px 안전 영역에서 여덟 번째 48px 선택지까지 스크롤로 완전히 닿고 고정 닫기 버튼과 겹치지 않아야 한다. 선택 구간 캡션은 실제 장착 목록에서 1~4개 파츠를 정확히 알리고, 3·4개 조합은 버튼 사이의 측정된 너비에 맞게 줄바꿈한다. 접근성 이름에는 완전한 파츠 이름을 유지한다.

## 완료 조건과 검증

1. 빠른/누적 해금, 벽돌 선행 조건, 네 파츠 정렬·중복·구간 독립성·휴면/복원·해제·잠김/미완성/비벽돌/실패 경계를 코어와 실제 버튼 입력으로 검증한다.
2. 실제 v1 두 세대, 기존 v2 두/세 파츠와 새 v2 네 파츠 파일의 읽기 전용 재개와 첫 쓰기를 별도 프로세스에서 확인한다. 기존 손상·경합·중단 복구도 유지한다.
3. 320×568, 360×800, 412×915 Windows 실제 화면에서 랜드마크 단독, 아치+랜드마크, 네 파츠 동시 표시, 다른 재질의 휴면, 여덟 번째 선택지의 스크롤 끝을 검증한다. 랜드마크층 위/아래와 기존 벽돌/아치층, 테라스·상단 마감 접합에서 빈 실루엣 행이 없어야 한다.
4. 고정 Godot 4.7.2/GUT 9.7.1 전체 검사, 저장 재시작, 별도 네이티브 캡처, 층 접합, 등록부 파일 크기·SHA-256·PNG 치수 검증의 실패·오류·보류가 0이어야 한다.

이 단계는 벽돌 랜드마크 파츠에 한정한다. 금속·유리/크리스털 파츠, 전체 탑 합성, 사람 관찰과 최신 Android 실기기 검증은 후속이다.

## 구현 및 확인 결과 (2026-09-25)

`brick_landmark`를 네 번째 벽돌 파츠로 연결했다. 기존 `bt_session_v2` 구간별 파츠 배열에 사전순으로 저장되며, 빠른 100줄/누적 300층 해금, 벽돌 구간 장착, 재질 변경 중 휴면 및 복원, 다른 세 파츠와의 공존이 적용됐다. 선택 구간의 다섯 번째 층에 일반 벽돌 또는 아치 창문과 조합된 시계 랜드마크 모듈을 그린다. 테라스의 아래층과 상단 장식의 마감 선택은 유지된다. 외벽 선택 시트에는 여덟 번째 선택지와 해금 조건을 표시하며, 선택 구간 캡션은 네 파츠까지 실제 장착 목록을 줄바꿈해 보여준다.

원본은 `art_source/visual_bible/render_brick_landmark.gd`와 편집 가능한 Godot 장면 두 개다. 투명 PNG 두 개와 공통 캔버스·앵커·층 간격 기록을 런타임 에셋에 추가했다. 에셋 등록부는 총 132개 항목이며, 이번에 추가한 원본·장면·PNG·메타데이터 6개에 대해 크기·SHA-256을 확인했다. PNG 두 개의 치수는 640×480이다.

작업 중 남겨진 고정 Godot 4.7.2/GUT 9.7.1 실행 기록은 **133개 테스트·3,600개 단언, 실패·오류·보류 0**이다. Windows 별도 프로세스 저장 기록은 **42/42 검사**를 통과했고, 실제 v1의 읽기 전용 재개와 기존 두/세 파츠 및 새 네 파츠 v2 세대의 재개·첫 쓰기를 포함한다. 최종 Windows 네이티브 캡처는 **15화면·186/186개 점검**을 통과했다. 별도의 큰 글씨·24px 안전 영역 캡처 **3화면·231/231개 점검**에서 320×568, 360×800, 412×915의 스크롤 끝 여덟 번째 48px 버튼이 닫기 버튼 위에 완전히 보인다. 랜드마크와 일반/아치/테라스/상단 마감 및 기존 목재·벽돌 경계 **8개 접합**에서 겹침 구간의 빈 실루엣 행이 0이었다.

증거: `tools/out/last_test_run.json`, `tools/out/gut.stdout.log`, `tools/out/w3_restart_latest.json`, `tools/out/phase2g_brick_landmark/summary.json`, 같은 폴더의 `native_final/`, `native_modal_check/`, `seams/` 및 `art_source/visual_bible/manifest.json`. 이번 현황 정리는 남아 있던 실행 기록과 코드를 확인했으며 검사를 새로 실행하지 않았다. 별도 독립 재실행은 기록에서 확인되지 않는다. 이 기록은 Windows와 로컬 에셋에 한정된다. 사람의 게임필 관찰, 최신 Android 빌드·설치·실기기 검증, 전체 탑 합성과 다른 재질 파츠는 아직 진행하지 않았다.
