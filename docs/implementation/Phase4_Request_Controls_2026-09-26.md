# Phase 4 요청 제한·운영 관측과 조각 트레이 복구

후속 [version 15 실기기·HTTP 확인 결과](Phase4_Controls_Device_Validation_2026-09-26.md)가 아래 최초 구현 시점의 미확인 항목을 갱신한다.

기준일: 2026-09-26. 이번 변경은 공개 서버 배포 전의 로컬 Phase 4 서버 보호 작업과 개인/주간 퍼즐의 조각 가독성 수정이다.

## 퍼즐 화면

- 사용자가 조각이 배경에 묻힌다고 알려 주어 기존 `tray.svg` 어두운 판과 세 칸 구분선을 대기 조각 뒤에 다시 그린다. 세 칸의 위치·터치 범위, 조각 크기, 배치 가능 표시, 공급 가중치, 저장 형식은 그대로다.
- 1칸 조각의 낮은 공급 가중치는 유지한다. [9월 25일 조정 기록](Piece_Tray_Refinement_2026-09-25.md)의 배경 제거 결정만 이번 요청으로 바뀌었다.
- 다음 Android 내보내기 프리셋은 versionCode 15다. 이번 변경의 APK 설치와 실기기 화면 확인은 아직 수행하지 않았다.

## 서버 보호와 관측

- 서버는 단일 프로세스 안에서 정규화한 클라이언트 IP와 요청 그룹별로 60초 고정 창을 유지한다. 계정 생성은 분당 12회, 계정 복구는 8회, 제출은 12회, 다른 API는 120회다. 초과 시 HTTP 429 `RATE_LIMITED`와 초 단위 `Retry-After`를 반환하며 요청 본문이나 게임 행동을 처리하지 않는다. 창 기록은 최대 8,192개이고 재시작하면 초기화된다.
- 재생 검증기는 최대 2개를 동시에 실행한다. 슬롯이 없으면 HTTP 503 `VERIFIER_BUSY`와 `Retry-After: 1`을 반환한다. 이미 검증한 같은 행동의 중복 제출은 기존과 같이 재생 없이 성공한다.
- `GET /health/live`는 프로세스 응답 여부를, `GET /health/ready`는 DB의 계정 표 조회와 고정 Godot 실행 파일·프로젝트 파일 존재를 확인한다. readiness는 실제 재생 검증 성공이나 외부 TLS 연결을 보증하지 않는다.
- 처리한 GET/POST API 응답마다 표준 출력에 JSON 한 줄을 남긴다. `request_id`, 메서드, 허용된 경로 이름, 상태 코드, 처리 시간만 포함한다. 응답에는 같은 `X-Request-ID`를 넣는다. 본문·토큰·쿼리·원본 IP는 로그에 남기지 않는다. 보존 기간과 경보는 배포 환경에서 설정해야 한다.
- 앱은 제한 또는 검증기 혼잡 오류를 한국어 재시도 안내로 보여 준다. 자동 재시도는 하지 않는다.

## 공개 프록시 연결 조건

서버는 계속 loopback에만 바인딩한다. TLS 역방향 프록시가 같은 기기에서 API로 접속할 때 `--trust-proxy-client-ip`를 켠다. 프록시는 외부 요청의 `X-Real-IP`를 **삭제한 뒤 실제 접속자의 단일 IP로 덮어써야** 한다. 옵션을 켜면 API는 정확히 한 개의 유효한 IP 헤더를 요구하며 없거나 중복/쉼표 형식이면 거절한다. 옵션이 꺼져 있으면 소켓 상대 주소만 사용하므로 같은 프록시 뒤의 사용자가 한도를 공유한다. API 포트를 외부에 직접 노출하지 않아야 한다.

운영자는 TLS 인증서, 프록시 접속/동시 연결 제한, 로그 수집·보존, 비공개 DB 백업과 복원, 규칙 버전별 재생기 유지, 다중 기기와 실제 UTC 주차 경계 확인을 별도로 마쳐야 한다. 이 변경만으로 공개 서비스 준비가 완료된 것은 아니다.

## 확인 범위

Python 서버 문법 확인과 고정 Godot 4.7.2의 프로젝트 가져오기는 오류 없이 끝났다. 변경 내역도 정적 검토했다. 이번 요청에서 서버 HTTP 동작, GUT 검사, 새 APK 빌드·설치, 실기기 화면 확인은 수행하지 않았으므로 수치·화면을 검증 결과로 기록하지 않는다. 9월 25일의 기존 147개 검사와 versionCode 14 실기기 결과는 이전 소스의 이력이다.
