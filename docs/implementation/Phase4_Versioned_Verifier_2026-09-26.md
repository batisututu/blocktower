# Phase 4 규칙 버전별 검증기 보존

기준일: 2026-09-26. 서버가 하나의 변경 가능한 게임 프로젝트로 모든 주간 행동을 재생하던 경로를 고쳤다.

## 구현

- 도전 표에 `rule_version`을 저장한다. 구 DB의 기존 행은 `bt_rules_v1`로 읽고, 새 도전에는 현재 규칙 버전을 발급한다. 응답은 저장된 값을 반환한다. `supply_profile`처럼 발급 이후 변경하지 않는다.
- v1 `GameSession`, 성장·조각 규칙, 두 공급 설정과 재생 스크립트를 [고정 재생기 프로젝트](../../services/phase4/verifiers/README.md)로 복사했다. `manifest.json`의 SHA-256은 이 복사본의 파일 변화를 감지한다. `.gitattributes`가 묶음의 줄바꿈 바이트를 그대로 보존해 다른 OS 체크아웃에서도 해시가 유지된다. 서버 기본 실행은 이 프로젝트를 사용한다.
- 서버는 제출 시 해당 도전의 버전으로 검증기를 선택한다. DB에 있는 버전이 등록되지 않았다면 시작하지 않고, 고정 프로젝트 파일이 바뀌면 검증을 거절한다. 다른 버전은 `--verifier-registry`로 등록할 수 있다. 같은 4.7.2 실행 파일을 쓰는 현재 구성에서 이후 엔진 변경이 필요하면 이전 실행 파일을 함께 보존한다.
- 클라이언트는 명시된 미지원 규칙 버전을 받으면 `UNSUPPORTED_VERSION`을 보여 주고 그 도전의 로컬 기록을 열거나 덮어쓰지 않는다. 기존 로컬 fixture처럼 버전 필드가 없는 입력은 v1로 해석한다.
- 새 버전 묶음 생성 도구 `tools/freeze_phase4_verifier.py`는 기존 목적지를 덮어쓰지 않는다. 실제 서버 배포에서는 현재 버전과 DB에 남은 과거 버전의 프로젝트·엔진 파일을 함께 배치한다.

## 다음 순서

Python 서버·묶음 생성기 문법 분석과 고정 Godot 4.7.2의 본 게임·v1 재생기 프로젝트 가져오기는 오류 없이 끝났다. 서버 기동, GUT/HTTP 회귀·Android 설치·실기기 음향은 별도 확인이다. 공개 TLS 주소, DB 복원 훈련과 다기기/UTC 주차 경계도 아직 남아 있다. 공개 서비스 준비 완료 판정은 하지 않는다.
