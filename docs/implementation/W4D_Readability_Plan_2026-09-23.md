# W4-D 화면 가독성 개선 계획

기준일: 2026-09-23. 이 채널의 Sol이 범위와 수용 기준을 정하고 최종 결과를 검증한다. 같은 Blocktower 작업 공간의 GPT-6-Luna가 코드 작성과 개발 실행을 담당한다. 사용자의 지시에 따라 실기기 설치·검증은 이후 작업으로 남긴다.

## 목표

모바일 세로 화면에서 글자가 작거나 색 구별이 어려워도 퍼즐의 현재 상태와 다음 행동을 이해할 수 있게 한다. Windows Godot 렌더에서 320×568, 360×800, 412×915와 320×568 상하 24px 안전 영역을 먼저 확인한다.

## 구현 범위

1. 설정에 큰 글씨 선택지를 추가한다. 기존 `bt_presentation_v1` 설정의 음량·음소거·진동·모션 값은 손실 없이 보존한다. 새 설정 형식이 필요하면 명시적으로 마이그레이션하고 손상 원본은 조용히 덮어쓰지 않는다.
2. 점수·최고점·자동/수동·클리어 견적·힌트·트레이·탑/설정 버튼·확인창·보상 문구가 큰 글씨에서도 잘리지 않도록 배치한다. 터치 버튼 높이 48px 이상, 보드의 기존 가로 우선 배치는 유지한다.
3. 유효/무효 배치, 대기 중인 완성 줄, 비활성 버튼, 클리어 완료를 색상 외의 윤곽·기호·문구로도 구별한다. 흑백 캡처에서 정보를 읽을 수 있어야 한다. 목재 B안의 기본 팔레트는 유지한다.
4. 배치·클리어·새 조각·새 최고 기록·게임오버의 연속 상태에서 안내가 보드를 가리거나 다음 입력을 방해하지 않도록 확인한다. 규칙·점수·RNG·저장 schema는 바꾸지 않는다.

## 수용 기준

- 고정 Godot 4.7.2/GUT 9.7.1 전체 테스트가 실패·오류·pending 없이 통과한다. 기존 저장 설정이 새 버전에서 그대로 복원되는 회귀 검사를 포함한다.
- 위 네 화면 조건에서 기본/큰 글씨의 실제 Godot 캡처를 남기고, 주요 문구·버튼·보드·하단 조작이 잘리지 않음을 확인한다.
- 유효/무효 preview, 완성 줄, 클리어 후 보상과 다음 조각, 확인창의 흑백 캡처에서 상태를 구별할 수 있다. 자동 체크와 사람의 화면 검토를 구분해 기록한다.
- 빠른 연속 배치·설정 전환·중단 후 복귀에서 확정 상태와 입력 잠금 경계가 기존과 같다. 실기기 성능·손가락 체감·진동 출력은 이 작업의 통과 근거로 쓰지 않는다.

Luna는 구현 파일과 자체 실행 로그를 보고한다. Sol은 변경 파일, 테스트 결과와 실제 캡처를 독립 확인하고 남은 결함을 Luna에 다시 전달한다.

## 구현 및 Sol 검증 결과

- Luna는 `bt_presentation_v2` 큰 글씨 설정, v1 값 네 가지 보존 마이그레이션, 작은 화면의 안전 영역과 스크롤 가능한 설정·확인창, 배치/완성 줄/비활성 버튼/클리어의 비색상 표시를 구현했다. 규칙·점수·RNG·게임 저장 형식은 변경하지 않았다.
- Sol이 고정 Godot 4.7.2/GUT 9.7.1 전체 스위트를 별도로 재실행했다. 99개 테스트, 3,070개 assertion, 실패 0, 오류 0, pending 0. 결과: `tools/out/gut_unit.xml`, `tools/out/last_test_run.json`.
- Luna의 Windows Godot 실제 캡처 18종과 자동 조건 검사 결과는 `tools/out/w4_native_a6f4a71ed0/summary.json`에 있다. Sol은 작은 화면·24px 안전 영역·큰 글씨 설정/확인창·흑백 배치 가능/불가·완성 줄·클리어 캡처를 직접 보고 잘림과 의미 손실이 없음을 확인했다.
- Sol이 대표 화면 6종을 `tools/out/w4d_sol_verify/summary.json`으로 독립 재실행했다. 30회 연속 입력도 `tools/out/w4d_sol_stress/stress_360x800.json`으로 재실행했고 각 입력 후 idle 복귀와 최종 화면/세션 일치를 확인했다.
- 이 결과는 Windows Godot 렌더 및 자동 입력 기준이다. Android 빌드·설치, 실제 손가락 가림·진동·기기 성능 검증은 사용자 요청대로 이후에 진행한다.
