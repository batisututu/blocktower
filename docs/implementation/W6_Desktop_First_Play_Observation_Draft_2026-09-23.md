# W6 데스크톱 첫 플레이 관찰 초안

기준일: 2026-09-23. W4-E 복합 보상 안내가 검증된 뒤 사용할 준비 문서다. 실제 참가자 관찰은 아직 하지 않았다. Android 실기기 평가는 사용자 지시에 따라 이후로 남긴다.

## 목적과 범위

Windows Godot 빌드의 첫 플레이에서 수동 클리어 규칙, 자동 전환, 보상·탑 성장의 이해, 반복 조작 피로를 확인한다. 재미·유지율의 합격률은 이 소규모 관찰로 정하지 않는다. 참가자의 퍼즐 게임 경험과 사용한 입력 장치를 기록해 결과를 해석한다.

## 진행 흐름

1. 조작 설명 없이 첫 화면을 보여주고 조각 배치와 완성 줄을 관찰한다. 막히면 참가자가 기대한 행동을 먼저 묻고, 이후 최소 안내를 제공한다.
2. 수동으로 완성한 줄을 언제·왜 지우는지 설명해 보게 한다. AUTO 전환 확인창의 예상 보상과 취소/확인 차이를 이해하는지 확인한다.
3. 첫 10층과 탑 화면을 관찰한다. 30층은 한 판에서 강제하지 않고 여러 판의 누적 목표로 다룬다. 보상 안내를 읽었는지, 자발적으로 탑을 여는지 기록한다.
4. 반복 배치·1줄/여러 줄 제거 후 소리, 화면 효과, 안내 속도와 피로를 질문한다. 무음·큰 글씨·움직임 줄이기 설정도 탐색 가능한지 확인한다.
5. 종료 시 참가자가 이해한 규칙과 가장 불편한 순간을 말하게 하고 관찰 기록과 구분해 남긴다.

## 기록 양식

| 항목 | 기록 방법 |
|---|---|
| 환경 | 빌드 식별자, Windows 해상도, 입력 장치, 설정, 참가자의 퍼즐 게임 경험 |
| 행동 | 첫 배치, 첫 완성 줄, 수동 클리어, AUTO 확인/취소, 첫 탑 방문의 순서와 도움 요청 여부 |
| 상태 | 각 순간의 점수·누적 층수·게임 모드와 저장된 세션 상태 |
| 혼동 | 기대한 결과, 실제 결과, 참가자 발화, 관찰자의 해석을 따로 기록 |
| 피로 | 반복 시 거슬린 효과/소리/알림과 조절 설정 사용 여부 |
| 후속 | 재현 가능한 결함, 문구/레이아웃 수정 후보, 규칙·밸런스 가설을 구분 |

참가자 조건, 1인 시간 상한, 중단 규칙, 관찰 기록의 보관 범위는 실제 모집·진행 전에 정한다. 동일 공급 정책/시드 비교를 하려면 세션별 시드와 규칙 버전을 먼저 고정한다. 개인 식별 정보와 자동 전송은 수집하지 않는 기본안을 사용한다.

## 세션 기록 카드 초안

아래 카드는 관찰자가 수기로 채운다. 참가자 이름이나 연락처는 게임 실행 도구와 이 카드에 넣지 않는다. 실제 사용 전 참가자 조건·동의·보관 기간을 결정한다.

| 필드 | 기입 내용 |
|---|---|
| 조건 | 익명 세션 코드, 수동→AUTO 또는 AUTO→수동 순서, 입력 장치, 화면 크기, 소리·움직임·큰 글씨 설정 |
| 재현 | 소스/엔진 식별자, 공급 정책·카탈로그 버전, 시작 시드, 조건별 독립 저장 폴더 |
| 첫 행동 | 첫 배치·첫 줄 완성·첫 클리어 시각, 도움 요청 전 기대 행동과 실제 행동 |
| 전환 | AUTO 확인창을 연 시각, 취소·확인 선택, 즉시 지워지는 줄의 예상과 실제 이해 |
| 성장 | 누적 10층·30층 도달 시각과 판 수, 자발적 탑 방문·구간 선택·해금 확인 여부 |
| 피로 | 반복 배치 중 거슬린 소리·진동·이펙트·안내의 구체적 순간, 설정 변경과 그 이유 |
| 종료 | 게임오버·중단 사유, 참가자 발화, 관찰자의 해석, 재현 결함과 개선 가설을 분리 |

같은 시드는 첫 조각 묶음을 재현한다. 조각 공급은 이후 보드 상태를 참조하므로 두 모드의 조작과 제거 시점이 달라지면 이후 조각열도 달라질 수 있다. 이 카드의 모드 비교를 전체 동일 조각열 비교로 해석하지 않는다. 실행 경로와 검증 기준은 [W6-A 준비 계획](W6A_Desktop_Playtest_Readiness_2026-09-23.md)을 따른다.
