# 생성기 v0.2 자체 기술검토

- 검토일: 2026-09-21 / 검토자: Codex(구현자와 동일).
- 사용자 요청: Claude Code 답변을 생략하고 Codex가 직접 검토. 이전 모델 전환 문의와 Claude 대기는 종료한다.
- 결론: **검토한 독립 생성기 범위에서 개발 착수를 막는 결함을 발견하지 못했다. W2 GameSession 계약·통합 작업을 시작할 수 있다.** 전체 게임·저장·모바일·밸런스 완료 판정은 아니다. 제3자 독립 검토로 표시하지 않는다.

## 검토 대상과 판단

대상은 [생성기](../../../game/scripts/core/generation/piece_generator.gd), 설정 Resource, [호출 계약](../../../game/scripts/core/contracts/piece_generation_contract.md), 기존 단위 테스트 및 대량 검사 코드다. 소스/계약 대조에 이어 생성기의 행 마스크를 사용하지 않는 좌표 기반 검사로 반례를 찾았다.

| 항목 | 검토 결과 |
|---|---|
| 계열/방향 확률 | 계열 정수 가중 → 계열 내 균등 방향. 0 가중치는 후보·fallback에서 제외. 계열이 많은 방향 때문에 추가 확률을 얻지 않음 |
| 유한 종료 | 후보 최대 4개, 마지막은 유한 활성 방향 열거. fallback 슬롯 목록은 Easy 유지 조건 아래 최소 한 개 이상 존재 |
| 사용자 설정 | 활성 Easy에 들어가는 조각이 없으면 전체 활성 계열에서 찾되 기존 Easy를 유지. 전체 활성 조각도 안 맞으면 false를 반환 |
| 조건부 보장 | 활성 조각 중 현재/클리어 후 들어가는 것이 있으면 증명 좌표를 반환. 기본 single 활성일 때 모든 유효 보드에서 조건 성립 |
| 클리어 | 원본 보드의 완성 행/열을 모두 찾은 뒤 합집합 제거. 현재 배치 가능한 뒤쪽 슬롯을 앞쪽의 클리어 후 배치보다 우선 |
| 게임오버 | 남은 트레이가 있고 현재 배치와 기존 클리어가 모두 불가능할 때. `MUST_CLEAR` 자체는 배치 보장이 아님 |
| RNG/소유권 | 지역 RNG, seed→state 복원, 엄격한 문자열/버전 검사. 반환 데이터 수정이 다음 호출에 영향을 주지 않음 |
| 버전 | 기존 19ID와 신규 10ID 분리, 정의/설정 해시 일치 확인. seed만 같은 다른 보드의 결과 동일성은 주장하지 않음 |
| 전체 트레이 해 | 한 수 보장은 세 조각 소진 보장이 아님. 기존 도미노 반례 검사 유지 |

## 발견한 검증 공백과 보완

기존 30만 트레이 검사는 기본 가중치를 사용했다. 따라서 임의 활성 계열 설정의 조건부 보장과 배치 불가능 판정을 직접 확인하는 범위를 추가했다. 런타임 수정이 필요한 반례는 발견하지 못했으며 생성기/카탈로그/가중치를 변경하지 않았다.

[추가 테스트](../../../game/tests/unit/test_piece_generator_redteam.gd):

1. **1,261개 배치 원점:** 각 조각이 보드 경계 안에서 차지할 수 있는 모든 원점에 정확히 그 조각 크기의 빈칸을 만들고 현재 배치 witness를 검증했다. 조각별 `(9-width)*(9-height)`의 합이다.
2. **6,380개 보드·조각 쌍:** 11가지 점유 확률을 반복한 220개 전체 보드 × 29방향. 독립 좌표 전수 검색으로 배치 가능/불가능 양쪽, 클리어 후 보드, 상태값을 비교했다.
3. **8,191개 활성 계열 조합:** 13계열의 비어 있지 않은 활성 부분집합 전수. 조합당 고정 시드 보드 한 개, 활성 가중치 `계열 인덱스+1`, 첫 활성 계열을 Easy로 지정했다. 재추첨 상한 0~3을 순환했다. 실제 활성 조각의 배치 가능성과 `guarantee_met`의 양방향 일치, Easy 유지, 비활성 공급 금지, 후보 상한, 증명 좌표를 확인했다. **모든 정수 가중치·Easy 부분집합·보드의 곱을 전수 검사한 것은 아니다.**
4. **슬롯 우선순위/반환값 소유권:** 앞 조각은 클리어 후, 뒤 single은 현재 배치 가능할 때 현재 배치를 선택하는지 확인했다. 반환 큐·checkpoint·진단 배열을 변경해도 같은 입력의 후속 결과가 유지됐다.

초기 실행에서 새 테스트의 총 원점 수를 1,333으로 잘못 적어 assertion 한 건이 실패했다. 실제 기하 합 1,261을 확인하여 **테스트 기대 개수만 수정**했고 최종 재실행은 모두 통과했다. 공급기 결함을 고친 것으로 기록하지 않는다.

## 실행 증거

**최종 5개 스크립트 / 25개 테스트 / 1,499개 assertion, 실패·오류·pending 0.** 추가 조합 루프는 일부 assertion 한 개로 집계된다.

- [최종 요약](review_2026-09-21/last_test_run.json), [JUnit](review_2026-09-21/gut_unit.xml), [실행 로그](review_2026-09-21/gut.stdout.log), [소스 해시](review_2026-09-21/source_manifest.json).
- 고정 Godot 4.7.2 / GUT 9.7.1의 바이너리·소스 해시 확인 후 실행.
- 최초 `pwsh -NoProfile -File tools/test.ps1`로 import 완료. 테스트 기대 개수 수정 후 `pwsh -NoProfile -File tools/test.ps1 -SkipImport`로 전체 25개 재실행.
- 이전 검증 manifest의 런타임·설정·계약·기존 테스트·도구 **11개 파일 해시가 모두 그대로**다. 기존 [30만 트레이 증거](piece_generation_simulation.json)는 같은 런타임의 증거로 유지하며 이번에 다시 생성한 결과라고 표시하지 않는다.

## 다음 단계

검토 대기는 해제했다. 다음 구현은 GameSession State/Action/Result 계약, 배치·수동/자동 클리어·트레이 소진 시 공급 한 번, 이후 SaveRepository의 전체 상태 커밋이다. 큐·RNG·batch_id·점수·성장을 같은 후보 상태로 저장하고 실패 재시도/재개/중복 액션을 검증해야 한다. 이 모듈의 공개 생성 경로는 `Generator.create()`이며 초기화되지 않은 `Generator.new()` 직접 사용은 지원 계약 밖이다.

새 알고리즘의 게임 통합을 시작할 수 있다는 판단과 출시 가능하다는 판단을 구분한다. 원본 시안 재현, 모바일 ARM64 동일 결과/성능, 사람 플레이의 난이도 검사는 기존 계획대로 남아 있다.
