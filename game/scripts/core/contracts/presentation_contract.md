# W4 presentation contract v1

The application owns one GameSession. PuzzleScreen renders its snapshot/view and submits actions through PresentationController. Preview never writes state. Old design_preview remains an explicitly separate review scene.

## Core read API and result events

`piece_for_slot(slot)` returns an owned catalog piece or an empty dictionary. `preview_placement(slot,x,y)` returns `{ok,error?,cells}` using the exact validator used by PLACE; cells are row-major indices only for a valid placement. `view()` adds `clear_lines` and `clear_points`. `CLEARED` adds owned `rows`, `columns`, `cells`, `styles` captured immediately before removal. `cells` is sorted, unique; `styles` has corresponding entries. Payload additions do not change saved schema or rules.

## Controller ownership

States: idle, dragging, committing, settling, modal, recovery. One pointer ID owns a drag; synthetic mouse events are ignored when actual touch events are used. Mouse ID is -1. Starting a drag captures batch and revision. Preview and release share origin conversion: pointer minus grab offset plus touch lift, transformed to board local coordinates, floor division as fallback with the bounded legal-anchor assist below; never unconditionally clamp out-of-bounds origins into the board. Dropping outside cancels without commit. Another finger cannot steal or finish the drag.

Dispatch uses the latest session_id/event_id, rejects stale drag/modal revisions, and submits once. Successful results alone produce committed presentation signals. Store latest presented revision to prevent repeated result playback. Failed writes retain authoritative state; uncertain/conflicting commits require reload. No animation callback mutates core state. Settle is explicitly cancellable and times out into the latest snapshot; cosmetic tails never extend board lock. Scene exit, focus loss and background cancel drag/settle and stop sounds; recovery remains locked.

## Screen and feedback

2026-09-21 UX refinement: board uses viewport width minus 24 logical px; secondary navigation stays above it. The current user request supersedes the historical side rails. Pointer-to-anchor assist searches only a 3x3 neighborhood within 0.70 cells, retains a previously valid anchor up to 0.90 cells, and revalidates against GameSession. It is disabled when the floating piece center is outside the board. Ghost and release always share the same anchor. No placement is created by decoration, late callbacks, or assistance alone.

Placement pop lasts 140ms. Clear visuals last 420ms (anticipation, axis sweep, staggered shrink and at most 36 deterministic fragments); input unlocks at 280ms. A new committed action or interruption replaces cosmetic tails. Reduced motion uses immediate state plus static reward, with no moving fragments. Exact score/floor counters remain authoritative throughout.

Touch pickup lifts the floating piece above its owning finger by at least 1.4 board cells and by half the piece height plus 0.65 cells for tall pieces. The same lift is used by preview and release; it does not change the legal board anchor or the saved action. The ghost remains authoritative when legal-anchor assistance is active. Clear visuals scale with the committed number of lines, stay local to the board, and never delay the 280ms input release. Clear reward text uses the strip below the board so it does not cover the next placement.

Use the pre-clear event payload as visual remnants above the committed board, treat remaining cosmetic particles as noninteractive after the 280ms release. Scale affects artwork only, not hit geometry. Commit success triggers visual snap/clear marks and bounded audio/haptic requests at the same presentation time. No full-screen flash, camera shake or gameplay RNG use. Reduced motion shows equivalent static state and zero/short fades. Score uses exact integers, with delta text rather than floating-point interpolation of large totals.

New Best celebration occurs once per run during this screen lifetime; resumed runs suppress historical celebration. Multiple segment/material/part notifications merge into the lower growth summary; clear reward uses one line below the board. Ordinary placement reward uses the same hint strip, and a new pickup dismisses any old reward and restores live guidance. Game over is derived from view, pending-clear states never show it. Results label persistent floors as cumulative; no invented per-run counter is added to v1 saves.

## 2026-09-23 HUD and flow refinement

The user approved the Mobbin-referenced redesign (Blocktower UI/UX 개선안 canvas) for the whole puzzle flow. This section supersedes the earlier wordmark/score-panel/lower-growth-label layout. Rules, saves, RNG and commit ordering are unchanged.

- **Top row:** a tower progress chip (native Button, `tower_button`) shows cumulative floors, the current segment progress (`partial_floors/10`) and `floors_to_next`, with the line tower icon. It never draws a sprite floor count. The settings icon button sits at the right. The puzzle screen no longer draws a wordmark or a score panel.
- **Score:** the exact score is the single dominant number, formatted with thousands separators. In the normal layout the best score sits above it with the trophy icon. In the compact layout (`usable_h < side+344`) it sits in the left of the score row. The font shrinks to fit; it never splits into rounded values. A streak chip shows the saved `streak` only when it is at least 2, and only in the normal layout.
- **Tray:** one shelf holds three contiguous lane hit rectangles (`tray_rects`), with a shared piece scale. A piece with no legal anchor on the current board (checked with `preview_placement`, without committing or drawing RNG) is dimmed, marked with a cross and labelled `놓을 곳 없음` when the lane is at least 80px tall. It stays pickable. While a piece is dragged, its lane keeps a 20% ghost.
- **Drag guidance:** valid previews read `[가능] +N점 · M줄 완성` when M lines would newly complete, otherwise `[가능] 놓을 수 있어요`. Newly completing lines draw a ready band. Lines that are already pending keep their own band.
- **Pending lines:** filled ready band, solid 2px outline and a dot at each end. The hint reads `[완성] N줄 대기 · 원할 때 지우세요`. With status `MUST_CLEAR` it reads `[완성] N줄 · 지워야 계속할 수 있어요` and the clear action gets a gold ring.
- **Clear dock:** the clear action and an adjacent auto-clear switch (`auto_button`, text-labelled `끔`/`켬`/`대기`) share one row. The clear action states are: pending lines `N줄 클리어` with `+P점 · 탑 +N층`; manual with no lines, a quiet disabled `대기 · 줄을 완성하세요`; automatic, disabled `자동 · 줄이 바로 지워져요`; drag with pending lines, the disabled material with `놓는 동안 잠겨요`; commit or settle `처리 중 · 잠시만요`; game over `결과 보기`.
- **Growth feedback:** after a committed clear that awards floors, the chip shows a `+N층` badge and a gold ring for 1.4s. Reduced motion shows the same badge without animation. Interruptions hide it. Segment and unlock counts stay in the strip notices, and exact facts stay in tower details and results.
- **Sheets:** every dialog is a bottom sheet fitted to its content inside the safe area. Content scrolls when taller than the space. Two-choice confirmations place the secondary action left and the primary action right. Settings adds a close control and moves `새 게임` into the actions. The auto-clear confirmation follows game design §4.4 copy (`수동 유지` / `지우고 자동 전환`) and shows the pending reward.
- **Results:** the title is `더 놓을 곳이 없어요`, with score and best cards, a cumulative tower card (mini tower, total floors, segment progress, floors to next) and any event facts. Actions are `다시 하기` (NEW_RUN, confirmed because the run is already over), `내 탑 보기` and `보드 보기`. No per-run floor counter is shown or saved.
- **Background:** the puzzle screen dims the architecture plate by 38% so the board and HUD remain the focus. The tower screen is unchanged.

## Local presentation preferences

`bt_presentation_v2`: reduced_motion bool, muted bool, volume integer 0..100, haptics bool, large_text bool. Defaults false/false/70/true/false for new settings. On read, a valid `bt_presentation_v1` file is migrated losslessly: its four existing values are retained and `large_text` starts false. The verified pending-file write replaces the valid v1 file only after the complete v2 JSON has been written and read back. If migration cannot be completed, the original remains untouched, its values stay active in memory with large text off, and writes are disabled with a visible warning. Invalid originals are never silently replaced. Independent JSON settings file, maximum 4096 bytes and strict exact keys/schema; missing settings use defaults. Preference write failure leaves prior in-memory settings and never changes game saves. Preferences do not alter auto_clear or supply RNG.

Large text is a presentation-only switch that raises HUD, button, dialog, and settings text sizes while retaining 48 logical-pixel touch targets. The wood B palette remains the default. Placement preview, pending clear lines, disabled actions, and committed clear results each carry a shape, symbol, or text cue that survives grayscale viewing; color remains supplementary.

For new settings files, haptics defaults to enabled; an existing saved haptics value remains authoritative. Pickup, successful placement, committed clear and segment completion have distinct bounded pulses. A clear has one haptic request even when placement and clear share a commit. Haptics respect the saved switch and application-active state. Audio uses original synthesized samples with bounded pitch variation and a six-player cap; frequent UI sounds may be dropped to preserve clear feedback. No sound or haptic plays for a failed save or for a preview alone.

## Planned acceptance

W5 lifecycle: AppRoot owns independent focus-loss and application-pause blockers. Input resumes only when both are cleared; duplicate/out-of-order paired notifications are idempotent. A newly booted screen inherits the current active state. PresentationController keeps `application_active` separate from phase: suspension cancels transient input/settle/modal but never clears recovery. Drag, submit and modal submission while inactive return/ignore SUSPENDED without error dialogs or commits.

Suspension stops audio, all feedback/button tweens, drag previews and pending celebrations. On resume PuzzleScreen rebuilds controls from the current committed session snapshot, preserves puzzle/tower location and restores mandatory recovery. There is no resume-time save, RNG draw, reward, replayed celebration or automatic dismissal of recovery. Startup recovery notices also remain mandatory. Controls created before suspension/layout replacement cannot execute delayed callbacks; removed modal controls cannot submit again. Only a new press can start a drag after resume, and late release/move events are ignored. Preferences callbacks obey the same lifecycle/control generation gate.

The user resumed combined physical-device validation on 2026-09-23. Root notice controls are invalidated synchronously on activation changes, then replaced with a guarded deferred callback after OS notification propagation unlocks the parent's child list. A stale callback cannot dismiss/retry before that replacement, and a deferred refresh cannot resurrect a dismissed or re-booted notice. The next combined device run must cover interrupted saves plus pause/resume during drag, clear tail, confirmation, settings and mandatory recovery; desktop simulated notifications are not Android lifecycle evidence.

## Tower segment jump (Phase 2-H)

`PuzzleScreen.selected_segment` is presentation state. When at least two segments exist, the tower screen exposes a 48px segment-jump action. Its sheet accepts an integer segment number from 1 through completed segments plus one partial segment when present. A missing, nonnumeric or out-of-range number leaves the sheet and selection unchanged with an inline error. A valid number closes the sheet and redraws the selected segment. Opening, canceling, validating and applying a jump never dispatch a `GameSession` action, write a save, alter representative selection or draw supply RNG. The existing previous/next buttons and facade/part editing remain tied to the selected segment. Enter submission and the sheet button obey the current UI epoch and application-active boundary; Back cancels the sheet.

## Whole-tower overview (Phase 3 MVP)

The whole-tower view is read-only presentation state. It shows exact cumulative floors, best score, completed and partial segment counts, material floor shares, the current selected segment and a shortcut to the representative segment. It renders at most 64 sampled silhouette bands regardless of tower height; this diagram is an explicitly condensed preview, while the text ratios are computed from exact sparse `growth.segment_styles` counts. No per-floor Node or texture is created. Segment jump from this view opens the selected detailed segment; Back returns to the prior detailed segment. Overview navigation never dispatches, saves, changes representative selection or advances RNG. The detailed segment view retains facade and part editing.

The overview dims its background for legible counts and shows one decimal place for nonzero material shares; shares below 0.1% remain visible as `0.1% 미만`. The selected ten-floor segment has a separate enlarged view for short screens. It reuses the same saved facade and part textures, supports previous/next segment movement, and returns to the detailed editing view through Back or its close action. Enlarging and moving within it are read-only presentation operations.

## Single-target appearance copy (Phase 3 MVP)

The detailed segment view opens a copy sheet only for a completed source when another completed target exists. The sheet accepts one target segment number, shows its current appearance and the copied appearance, and offers cancel. Invalid, partial, same-source and unchanged targets stay in the sheet without dispatch. Confirmation submits exactly one `COPY_SEGMENT_APPEARANCE` action through `PresentationController.submit_modal`, so stale revisions and commit failures retain their existing behavior. After a successful commit, the detailed view selects the target. No bulk copy or transient undo is part of this single-target action.

Android back is owned by AppRoot with SceneTree.quit_on_go_back disabled: close the current modal first, cancel an active drag, then return from tower to puzzle. A plain puzzle/root notice back may exit. Recovery modals remain locked. Back navigation never commits state or changes RNG; desktop Escape uses the same screen routing without exiting.
